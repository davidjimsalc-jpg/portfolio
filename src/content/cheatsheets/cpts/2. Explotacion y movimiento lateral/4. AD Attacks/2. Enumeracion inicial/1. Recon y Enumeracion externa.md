
La recon y enum externa puede servir para:

- Validar la info que nos dan en la documentacion
- Asegurarnos de que estamos frente al alcance apropiado
- Buscar informacion de acceso publico que puede ayudarnos en la prueba


## Que buscamos

- Espacio IP
- Informacion del dominio
- Listas de nombres, correos, passwords...
- Revelaciones de datos como archivos .pdf, .ppt...
- Brechas de datos


## Donde estamos buscando

- Registradores de ASN/IP: [IANA](https://www.iana.org/), [arin](https://www.arin.net/) para buscar en las Américas, [RIPE](https://www.ripe.net/) para buscar en Europa, [BGP Toolkit](https://bgp.he.net/)

- Resgistradores de dominio y DNS: [Domaintools](https://www.domaintools.com/), [PTRArchive](http://ptrarchive.com/), [ICANN](https://lookup.icann.org/lookup), peticiones manuales de registros DNS contra el dominio en cuestión o contra servidores DNS conocidos, como `8.8.8.8`

- Redes sociales: LinkedIn, Twitter, Facebook...

- Sitios web publicos de la empresa: pueden tener informacion importante incrustada, paginas "sobre nosotors", "contactanos"...

- Espacion de almacenamiento en la nube y de desarrollo: [GitHub](https://github.com/), [Buckets de AWS S3 y contenedores de almacenamiento de Azure Blog](https://grayhatwarfare.com/), [Búsquedas en Google usando "Dorks"](https://www.exploit-db.com/google-hacking-database)

- Fuentes de datos de brechas: [HaveIBeenPwned](https://haveibeenpwned.com/), [Dehashed](https://www.dehashed.com/)




## Encontrando espacio de direcciones

BGP-Toolkit alojado en [Hurricane Electric](http://he.net/)

![[Pasted image 20260924133317.png]]

Nos permite investigar que bloque de direcciones estan asignados a una organizacion y dentro de que ASN se encuentran

- Introducimos el dominio o una direccion IP y esta buscara los resultados que encuentre

Muchas empresas grandes y pequeñas autoalojan su infraestructura y son tan grandes que puede que tengan su propio ASN (no es tipico), lo normal es alojarlo en un tercero como Clouudflare, Google Cloud....

	La parte de la infraestructura gestionada o autoalojada por terceros debe quedar fuera del alcance

Es por esto que a veces el cliente debera tener aprovacion del proveedor de hosting de terceros antes de realizar las pruebas


## DNS

Esto es una forma de validar el alcance y descubrir mas hosts accesibles que no fueron incluidos por el cliente

Sitios web: [domaintools](https://whois.domaintools.com/) y [viewdns.info](https://viewdns.info/)

Podemos obtener datos desde resolucion DNS hasta prueba DNSSEC y si el sitio es accesible en paises restringidos. Podriamos encontrar hosts, subdominios... adicionales fuera del alcance pero que parecen interesantes, hacer una lista y mandarlos a cliente

![[Pasted image 20260924134407.png]]


## Datos publicos

Las RRSS nos pueden dar info sobre el equipo, organizacion, implementacion sw y seguridad...

Ejemplo de una oferta de trabajo para administrador de sharepoint:

![[Pasted image 20260924134909.png]]

Sitios web alojados por la organizacion para recopilar correos, numeros de telefono, organigramas, documentos. Estos (sobre todo los documentos incrustados) podrian tener enlaces hacia infraestructura interna

Con el creciente uso de sitios como GitHub, el almacenamiento en la nube de AWS y otras plataformas alojadas en la web, los datos también pueden filtrarse

Herramientas como [Trufflehog](https://github.com/trufflesecurity/truffleHog) y sitios como [Greyhat Warfare](https://buckets.grayhatwarfare.com/) son recursos fantásticos para encontrar estas migas de pan.


## Proceso ejemplo de enumeracion

Sobre el dominio `inlanefreight.com`


1. Comprobar datos de ASN/IP y dominio

![[Pasted image 20260924135541.png]]

Aqui vemos alguna info interesante:

- Direccion IP: 134.209.24.248
- Servidor de correo: mail1.inlanefreight.com
- Servidores de nombres: NS1.inlanefreight.com y NS1.inlanefreight.com

	Como no es una gran corporacion no esperabamos que tuviese su propio ASN


![[Pasted image 20260924135739.png]]

Al validar la IP que habiamos encontrado antes, vemos que ambos resultados coinciden con inlanefreigh.com

Vamos ahora a validar los servidores de nombres:

```
nslookup ns1.inlanefreight.com
```
![[Pasted image 20260924135910.png]]

Ahora tenemos 2 nuevas direcciones IP para agregar a la lista (hay que asegurarse de que esten en el alcance)


2. Buscamos en redes sociales

	Como inlanefreight es una empresa fiticia no tiene presencia en redes sociales


3. Buscamos documentos usando google dorks y el dominio:

```
filetype:pdf inurl:inlanefreight.com
```
![[Pasted image 20260924140146.png]]

Aqui aparece un documento, descargamos una copia


4. Buscamos direcciones de correo

```
intext:"@inalenfreight.com" inurl:inlanefreight.com
```
![[Pasted image 20260924140306.png]]

Obtenemos un resultado prometedor en una pagina de contacto y su info de contacto


5. Comprobamos los datos de contacto del correo en  la [página de contacto](https://www.inlanefreight.com/index.php/contact/) que hemos encontrado

![[Pasted image 20260924140456.png]]

Aqui aparecen correos internacionales que comparten una nomenglatura y podemos usar para password spraying o para phishing


6. Recoleccion de nombres de usuario en LinkedIn:

[linkedin2username](https://github.com/initstring/linkedin2username): para extraer datos de LinkedIn y crear nombres de usuario seguna la info recolectada


7. Busqueda de credenciales: 

[Dehashed](http://dehashed.com/): herramienta de busqueda de credenciales en texto claro y hashes de contraseñas en brechas de datos

```
sudo python3 dehashed.py -q inlanefreight.local -p
```
![[Pasted image 20260924140735.png]]

[script usado](https://github.com/mrb3n813/Pentest-stuff/blob/master/dehashed.py)

[alternativa](https://github.com/sm00v/Dehashed)
