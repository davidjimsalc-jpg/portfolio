## TTPs

Empezaremos con una identificacion pasiva seguida de la validacion activa de resultados para averiguar mas de cada host. Una vez sepamos los hosts existentes podemos pasar a sondear estos hosts

#### Identificando hosts

1. Escuchemos la red con Wireshark o Tcpdump

```
sudo -E wireshark
```

	Los paquetes ARP nos informan de hosts: 172.16.5.5, 172.16.5.25 172.16.5.50, 172.16.5.100, y 172.16.5.125

![[Pasted image 20260924145610.png]]

	MDNS nos informa del host ACADEMY-EA-WEB01

![[Pasted image 20260924145642.png]]

Si estamos en un host sin GUI podemos usar  [tcpdump](https://linux.die.net/man/8/tcpdump), [net-creds](https://github.com/DanMcInerney/net-creds), y [NetMiner](https://www.netminer.com/en/product/netminer.php), para las mismas funciones:

```
sudo tcpdump -i INTERFAZ
```
![[Pasted image 20260924145811.png]]

En algunos hosts tendremos ya herramientas de monitorizacion de red como `pktmon.exe`

	NOTA: SIEMPRE ES BUENO GUARDAR EL TRAFICO EN UN ARCHIVO PCAP


2. [Responder](https://github.com/lgandx/Responder-Windows): herramienta que escucha, analisis y envenamiento de solicitudes y respuestas LLMNR, NTB-NS y MDNS 

En este caso usaremos Analyze mode para escuchar pasivamente y no enviar paquetes envenenados:

```

```

Nos saldran solicitudes en nuestra sesion donde podremos observar hosts unicos que no mencionamos previamente y anotaremos


3. Comprobacion activa de barrido ICMP con [Fping](https://fping.org/) hacia una lista de multiples hosts

```

```
![[Pasted image 20260924150533.png]]

-a: mostrar los objetivos vivios

-g: generar una lista de objetivos desde la red CIDR

	Podemos combinar los resultados exitosos y los encontrados en las comprobaciones pasivas en una lista para un escaneo mas detallado con nmap

## Identificando usuarios

Si nos dan un usuario para comenzar las pruebas, necesitaremos encontrar un punto de apoyo en el dominio, que puede ser mediante:

- Credenciales en texto plano de usuario del dominio
- Hashes NTLM de usuario de dominio que podamos crackear
- Shell SYSTEM en maquina asociada al dominio
- Shell en contexto de un usuario del dominio


#### Kerbrute - Enumeracion interna de nombres de usuario de AD

[Kerbrute](https://github.com/ropnop/kerbrute): puede ser una opción más sigilosa para la enumeración de cuentas de dominio. Aprovecha el hecho de que los fallos de preautenticación de Kerberos a menudo no activarán registros ni alertas

## Identificando vulnerabilidades potenciales

La cuenta SYSTEM es una cuenta integrada en SO Windows con el nivel de acceso mas alto y se usa para ejecutar la mayoria de servicios Windows o tambien es comun que servicios o herramientas de terceros se ejecuten como SYSTEM

SYSTEM en una maquina unida a un dominio, podra enumerar el AD haciendose pasar por una cuenta maquina del dominio que es casi equivalente a tener una cuenta de usuario de dominio

Formas de obtener SYSTEM privs:

- Explotaciones remotas de Windows como EternalBlue o BlueKeep
- Abuso de servicio que se ejecuta como SYSTEM o abusar de privs SeImpersonate y usar [Juicy Potato](https://github.com/ohpe/juicy-potato) (a partir de Server 2019 no funciona siempre)
- 0 days de escalada de privs
- Acceso administrador en un host unido al dominio con una cuenta local y usar Psexec para lanzar una ventana cmd como SYSTEM


Como SYSTEM podemos:

- Enumerar el dominio usando herramientas integradas o herramientas ofensivas como BloodHound y PowerView.
- Realizar ataques de Kerberoasting / ASREPRoasting dentro del mismo dominio.
- Ejecutar herramientas como Inveigh para recopilar hashes Net-NTLMv2 o realizar ataques de retransmisión SMB.
- Realizar suplantación de token (token impersonation) para secuestrar una cuenta de usuario de dominio privilegiada.
- Llevar a cabo ataques de ACL.
