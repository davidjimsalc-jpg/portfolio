## Enumeracion de ACL con PowerView

Si ejecutamos `Find-InterestingDomainAcl` recibiremos una cantidad ingente de informacion

```
Find-InterestingDomainAcl
```
![[Pasted image 20260928135433.png]]

Es probable que nunca terminemos de revisarlo todo o que no encontremos nada interesante

1. Realizar una enumeracion dirigida a partir de un usuario sobre el que tenemos control (en este caso usaremos a wley). Vamos a ver si ese usuario tiene algun ACL interesante que podamos aprovehar

- Necesitaremos el SID del usuario objetivo

```
Import-Module .\PowerView.ps1
$sid = Convert-NameToSid wley
```

2. Usamos Get-DomainObjectACL para hacer la busqueda dirigida. En el siguiente ejemplo estamos rastreando a traves del SID quien tiene el derecho dado sobre un objeto

	El comando tarda unos minutos en ejecutarse

```
Get-DomainObjectACL -Identity * | ? {$_.SecurityIdentifier -eq $sid}
```
![[Pasted image 20260928140359.png]]

	Vemos que wley tiene sobre damundsen ExtendRight pero no sabemos el valor del ObjectAceType porque esta en un formato no legible para humanos (GUID)

3. Podemos buscar 00299570-246d-11d0-a768-00aa006e0529 en google y ver [esta](https://docs.microsoft.com/en-us/windows/win32/adschema/r-user-force-change-password) pagina que dice que el usuario tiene derecho de forzar el cambio de contraseña de otro

- Otra opcion es realizar una busqueda inversa en PS:

```
$guid= "00299570-246d-11d0-a768-00aa006e0529"

Get-ADObject -SearchBase "CN=Extended-Rights,$((Get-ADRootDSE).ConfigurationNamingContext)" -Filter {ObjectClass -like 'ControlAccessRight'} -Properties * |Select Name,DisplayName,DistinguishedName,rightsGuid| ?{$_.rightsGuid -eq $guid} | fl
```
![[Pasted image 20260928140636.png]]

	Pero es muy ineficiente

- Otra forma es usar -ResolveGUIDs en PowerView

```
Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $sid}
```
![[Pasted image 20260928140729.png]]


## Como obtener ACLs sin PowerView

1. Obtenemos lista de usuarios

```
Get-ADUser -Filter * | Select-Object -ExpandProperty SamAccountName > ad_users.txt
```

2. Leemos cada linea con un foreach y usamos Get-Acl para recuperar la info ACL de cada usuario. Solo seleccionamos la propiedad Access IdentitiyReference al usuario wley que controlamos

```
foreach($line in [System.IO.File]::ReadLines("C:\Users\htb-student\Desktop\ad_users.txt")) {get-acl "AD:\$(Get-ADUser $line)" | Select-Object Path -ExpandProperty Access | Where-Object {$_.IdentityReference -match 'INLANEFREIGHT\\wley'}}
```
![[Pasted image 20260928141014.png]]

	Podriamos seguir los mismos pasos que en PowerView para obtener el valor real de ObjectType


## Siguiendo

1. Antes de realizar nada, miramos hacia donde nos llevaria el control de `damundsen`

```
$sid2 = Convert-NameToSid damundsen

Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $sid2} -Verbose
```
![[Pasted image 20260928141431.png]]

Vemos que `damundsen` tiene GenericWrite sobre `Help Desk Level 1`. Entre otras cosas, podriamos añadir cualquier usuario a este grupo y heredar cualquier derecho que este grupo tenga aplicado

2. Si buscamos los derechos conferidos a este grupo no nos da nada interesante

```
$sid3 = Convert-NameToSid "Help Desk Level 1"
Get-DomainObjectAcl -ResolveGUIDs | Where-Object {$_.SecurityIdentifier -eq $sid3}
```

3. Podemos mirar si es un grupon anidado y vemos que esta anidado al grupo `Information Technology` obteniendo cualquier derecho de este grupo

```
Get-DomainGroup -Identity "Help Desk Level 1" | select memberof
```
![[Pasted image 20260928141759.png]]

4. Miramos ahora los derechos de `Information Technology` y vemos un GenericAll para el usuario `adunn`:

- Modificar la pertenencia a grupos
- Forzar el cambio de una contraseña
- Realizar un ataque de Kerberoasting dirigido e intentar crackear la contraseña del usuario si es débil

```
$sid4 = Convert-NameToSid "Information Technology"

Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $sid4} -Verbose
```
![[Pasted image 20260928142412.png]]

5. Por ultimo miramos si `adunn` tiene algun tipo de acceso interesante que aprovechar

```
$adunnsid = Convert-NameToSid adunn

Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $adunnsid} -Verbose
```
![[Pasted image 20260928142504.png]]

	Vemos que tenemos derechos `DS-Replication-Get-Changes` y `DS-Replication-Get-Changes-In-Filtered-Set` sobre el objeto de dominio. Esto significa que este usuario puede ser aprovechado para realizar un ataque DCSync


## Enumeracion de ACL con BloodHound

Tomemos los datos que recopilamos anteriormente con el ingestor SharpHound y subámoslos a BloodHound

1. Establecer el usuario `wley` como nuestro nodo de partida
2. Seleccionar la pestaña `Node Info`
3. Desplazarnos hacia abajo hasta `Outbound Control Rights`
	Esta opción nos mostrará los objetos sobre los que tenemos control directamente, a través de la pertenencia a grupos, y el número de objetos que nuestro usuario podría llevarnos a controlar a través de rutas de ataque de ACL en `Transitive Object Control`
4. Si hacemos clic en el `1` junto a `First Degree Object Control`, vemos el primer conjunto de derechos que enumeramos, `ForceChangePassword` sobre el usuario `damundsen`

![[Pasted image 20260928142730.png]]

Si hacemos clic derecho en la línea entre los dos objetos, aparecerá un menú. Si seleccionamos `Help`, se nos presentará ayuda sobre cómo abusar de esta ACE, incluyendo:

- Más información sobre el derecho específico, herramientas y comandos que se pueden usar para llevar a cabo este ataque
- consideraciones de Seguridad Operacional (Opsec)
- Referencias externas.

![[Pasted image 20260928142756.png]]


5. Si hacemos clic en el `16` junto a `Transitive Object Control`, veremos la ruta completa que hemos enumerado minuciosamente más arriba. A partir de aquí, podríamos aprovechar los menús de ayuda de cada borde (edge) para encontrar las mejores formas de llevar a cabo cada ataque
![[Pasted image 20260928142832.png]]

6. Finalmente, podemos usar las consultas predefinidas (pre-built queries) en BloodHound para confirmar que el usuario `adunn` tiene derechos de DCSync

![[Pasted image 20260928142852.png]]
