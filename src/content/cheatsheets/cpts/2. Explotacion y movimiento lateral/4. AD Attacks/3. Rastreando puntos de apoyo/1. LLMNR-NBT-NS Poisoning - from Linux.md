
Envenenamiento de red (network poisoning) y pulverización de contraseñas (password spraying)

Realizamos estas acciones con el objetivo de adquirir credenciales validas en texto plano para una cuenta de usuario del dominio y obtener un punto de apoyo

## Manual basico de LLMNR y NBT-NS

LLMNR: [Resolución de Nombres de Multidifusión de Vínculo Local](https://datatracker.ietf.org/doc/html/rfc4795) (5355 UDP)
NBT-NS: [Servicio de Nombres NetBIOS](https://docs.microsoft.com/en-us/previous-versions/windows/it-pro/windows-2000-server/cc940063\(v=technet.10\)?redirectedfrom=MSDN) (137 UDP)

Sirven como metodos alternativos de resolicion de hosts por si la resolucion DNS falla. Si DNS falla, la maquina preguntara a las demas maquinas en la red local la direccion correcta del host a traves de LLMNR que esta basado en DNS permitiendo a los hosts en la misma red local realizar resoluciones de nombres

Cuando usamos LLMNR/NBT-NS cualquier host puede resopnder por lo que usaremos `Responder` para envenenar las solicitudes, suplantando a una fuente autorizada de resolucion de nombres en el dominio broadcast y respondiendo al trafico LLMNR/NBT-NS como si tuvieramos la respuesta

La solucion de autenticacion capturada puede ser usada contra otro protocolo diferente LDAP en el mismo host


## Ejemplo rapido de envenenamiento de LLMNR/NBT-NS

1. Un host se intenta conectar a un servidor de impresion `\\print01.inlanefreight.local` pero escribe por accidente `\\printer01.inlanefreight.local`
2. DNS responde que el host es desconocido
3. Host retransmite a toda la red local preguntando por `\\printer01`
4. Nosotros tendremos el `Responder` abierto y le respondemos que somos `\\printer01`
5. El host cree en la respuesta y envia una solicitud de autenticacion con el NOMBRE y NTLM
6. Lo capturamos y crackeamos offline o usamos para ataque de retransmision SMB 


## TTPs

Se pueden usar varias herramientas para intentar el envenenamiento de LLMNR y NBT-NS:

| Herramienta                                                                                | Descripcion                                                                                                                        |
| ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| [Responder](https://github.com/lgandx/Responder)                                           | Realiza **poisoning de LLMNR, NBT-NS y mDNS** para interceptar solicitudes de resolución de nombres y capturar credenciales/hashes |
| [Inveigh.ps1](https://github.com/Kevin-Robertson/Inveigh/blob/master/Inveigh.ps1)          | Alternativa a Responder escrita en **PowerShell**, orientada a realizar **spoofing y poisoning** en la red.                        |
| [C# Inveigh (InveighZero)](https://github.com/Kevin-Robertson/Inveigh/tree/master/Inveigh) | Versión en **C# de Inveigh**, con consola interactiva para realizar poisoning y gestionar los **usuarios/hashes capturados**.      |
| [Metasploit](https://www.metasploit.com/)                                                  | Tiene varios escáneres y módulos de suplantación incorporados para lidiar con ataques de envenenamiento                            |


## Accion

En la Enum Inicial usamos Responder en modo Analisis Pasivo (escucho cualquier solicitud de resolucion pero no las respondio ni envio paquetes)

Ahora haremos Responder respondera:

```
responder -h
```
![[Pasted image 20260925141959.png]]

-A: nos pone en modo analisis permitiendonos ver solicitudes NBT-NS, LLMNR, BROWSER sin envenenar

-wf: -w iniciara un servidor proxy malicioso WPAD mientras que -f tomara huella digital del SO y la version del host remoto

-v: verbose

-F: forzar autenticacion NTLM 
-P: forzar autenticacion del proxy
	Aunque pueden causar que aparezca una ventana de autenticaicon

Con esta conf, Responder escuchara y respondera a cualquier solicitud que vea en la red. Si consigue algun hash, lo imprimira por pantalla y lo escribira en un archivo de registro (`/usr/share/responder/logs/NOMBRE_MODULO-TIPO_HASH-IP_CLIENTE.txt`) pero tambien se mostrara en consola

Ejemplo: SMB-NTLMv2-SSP-172.16.5.25
