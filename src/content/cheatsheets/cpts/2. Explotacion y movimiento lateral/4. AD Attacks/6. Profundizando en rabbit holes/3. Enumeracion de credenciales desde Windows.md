
Herramientas para enumerar AD desde un host Windows


## Modulo de PS ActiveDirectory

[módulo de PowerShell ActiveDirectory](https://docs.microsoft.com/en-us/powershell/module/activedirectory/?view=windowsserver2022-ps): grupo de cmdlets de PS para administrar un entorno AD

1. Asegurarnos de que este importado:

```
Get-Module
```
![[Pasted image 20260927110049.png]]

	Listara todos los modulos disponibles, su version y posibles comandos para uso. Tambien muestra scripts y Gits personalizados

2. Hemos visto que NO esta importado asi que vamos a importarlo:

```
Import-Module ActiveDirectory
Get-Module
```
![[Pasted image 20260927110212.png]]

3. [Get-ADDomain](https://docs.microsoft.com/en-us/powershell/module/activedirectory/get-addomain?view=windowsserver2022-ps): para obtener informacion del dominio:

```
Get-ADDomain
```
![[Pasted image 20260927110304.png]]

	Imprime info como el SID del dominio, nivel funcional, cualquier dominio hijo

3. [Get-ADUser](https://docs.microsoft.com/en-us/powershell/module/activedirectory/get-aduser?view=windowsserver2022-ps): si filtramos por `ServicePrincipalName` nos dara una lista de cuentas susceptibles a Kerberoasting

```
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName
```
![[Pasted image 20260927110455.png]]

4. [Get-ADTrust](https://docs.microsoft.com/en-us/powershell/module/activedirectory/get-adtrust?view=windowsserver2022-ps): verificar relaciones de confianza de dominio

```
Get-ADTrust -Filter *
```
![[Pasted image 20260927110537.png]]

	Imprime cualquier relacion de confianza que tenga el dominio viendo si son dentro del bosque o con dominios de otros bosques. Ademas de la direccion de la confianza y el nombre del dominio con el que se tiene relacion

5. [Get-ADGroup](https://docs.microsoft.com/en-us/powershell/module/activedirectory/get-adgroup?view=windowsserver2022-ps): informacion de grupos AD

```
Get-ADGroup -Filter * | select name
```
![[Pasted image 20260927110711.png]]


6. Podemos tomar los nombres interesantes y obtener mas informacion de ellos:

```
Get-ADGroup -Identity "Backup Operators"
```
![[Pasted image 20260927110822.png]]

7. [Get-ADGroupMember](https://docs.microsoft.com/en-us/powershell/module/activedirectory/get-adgroupmember?view=windowsserver2022-ps): lista de miembros usando cmdlet

```
Get-ADGroupMember -Identity "Backup Operators"
```
![[Pasted image 20260927110900.png]]

	Podemos ver que la cuenta backupagent pertenece al grupo Backup Operators


## PowerView

[PowerView](https://github.com/PowerShellMafia/PowerSploit/tree/master/Recon): herramienta PS para obtener conciencia situacional dentro de un entorno AD. Enumeracion informacion de usuarios, equipos, grupos, ACL, confianzas....

Capacidades de PowerView:

![[Pasted image 20260927111111.png]]![[Pasted image 20260927111126.png]]![[Pasted image 20260927111138.png]]


1. [Get-DomainUser](https://powersploit.readthedocs.io/en/latest/Recon/Get-DomainUser/): proporciona informacion sobre todos los usuarios o usuarios especificos

```
cd C:\Tools\
Import-Module .\PowerView.ps1

Get-DomainUser -Identity mmorgan -Domain inlanefreight.local | Select-Object -Property name,samaccountname,description,memberof,whencreated,pwdlastset,lastlogontimestamp,accoun
```
![[Pasted image 20260927111250.png]]

2. [Get-DomainGroupMember](https://powersploit.readthedocs.io/en/latest/Recon/Get-DomainGroupMember/): enumerar informacion de grupos de dominio o de un grupo especifico. `-Recurse` hace que si se encuentra algun grupo que sea parte del grupo objetivo (membresia de grupo anidada) liste sus miembros

	En la siguiente salida se ve como el grupo `Secadmins` es parte del grupo `Domain Admins`

```
Get-DomainGroupMember -Identity "Domain Admins" -Recurse
```
![[Pasted image 20260927111503.png]]

	Ahora sabemos a quien dirigirnos para una posible escalada de privs


3. Enumerar mapeos de confianza:

```
Get-DomainTrustMapping
```
![[Pasted image 20260927111608.png]]


4. [Test-AdminAccess](https://powersploit.readthedocs.io/en/latest/Recon/Test-AdminAccess/): probar el acceso de administrador local en la maquina actual o en una remota

```
Test-AdminAccess -ComputerName ACADEMY-EA-MS01
```
![[Pasted image 20260927111646.png]]

	Vimos en una de las salidas anteriores que nuestro usuario es admin en ACADEMY-EA-MS01. Podemos probar esto en diferentes hosts para ver si tenemos acceso administrativo

5. Buscamos usuarios con atributo SPN para ataques Kerberoasting:

```
Get-DomainUser -SPN -Properties samaccountname,ServicePrincipalName
```
![[Pasted image 20260927111829.png]]

## Recursos compartidos

Permiten a los usuarios de un dominio acceder rápidamente a información relevante

[Snaffler](https://github.com/SnaffCon/Snaffler): es una herramienta que nos puede ayudar a obtener credenciales u otros datos sensibles en el entorno AD. Obtiene una lista de hosts dentro del dominio y luego enumera los hosts en busca de shares y directorios legibles. Una vez hecho esto itera a traves de cualquier directorio elgible y busca archivos que puedan servir para mejorar nuestra posicion

Tenemos que ejecutarlo desde un host unido al dominio

```
Snaffler.exe -s -d inlanefreight.local -o snaffler.log -v data
```

- -s: imprima los resultados en consola
- -d: dominio
- -o: escriba los resultados en un archivo
- -v: nivel de verbosidad

![[Pasted image 20260927112451.png]]

Podemos encontrar contraseñas, claves SSH, archivos de configuración u otros datos que pueden ser utilizados para ampliar nuestro acceso

## Bloodhound

Puede identificar rutas de ataque (attack paths) en un entorno de AD analizando las relaciones entre objetos

Primero, debemos autenticarnos como un usuario de dominio desde un host de ataque Windows posicionado dentro de la red (pero no unido al dominio) o transferir la herramienta a un host unido al dominio

Para nuestros propósitos, trabajaremos con SharpHound.exe

1. Ejecutamos SharpHound para la recopilacion de informacion del dominio

```
.\SharpHound.exe --help
```
![[Pasted image 20260927112937.png]]

```
.\SharpHound.exe -c All --zipfilename ILFREIGHT
```
![[Pasted image 20260927112953.png]]

2. Pasamos el zip a nuestro host de ataque o cargar bloodhound en el host de la red y abrirlo desde ahi

	Las creds de bloodhound de la maquina son: neo4j: HTB_@cademy_stdnt!

3. Despues de abrir Bloodhound --> Upload Data > ZIP > Open
4. Busquedas:

- Podemos escribir `domain:` en la barra de busqueda (parte superior izq) y elegir `INLANEFREIGHT.LOCAL`
- Podemos echar un vistazo a la info de los nodos
- Podemos ir a la pestaña de `Analysis`> `Find Computers with Unsupported Operating Systems` para encontrar sistemas operativos obsoletos

![[Pasted image 20260927113355.png]]


	A menudo veremos usuarios con derechos de administrador local en su host o que ocupan un rol suficientemente alto en la organización como para exigir estos derechos. Otras veces veremos derechos de administrador local excesivos distribuidos por toda la organización


- Podemos ejecutar la consulta `Find Computers where Domain Users are Local Admin` (Buscar Equipos donde los Usuarios del Dominio son Administradores Locales) para ver rápidamente si hay algún host donde todos los usuarios tienen derechos de administrador local

	Si este es el caso, entonces cualquier cuenta que controlemos puede ser utilizada típicamente para acceder al host o hosts en cuestión, y podríamos recuperar credenciales de la memoria o encontrar otros datos sensibles


![[Pasted image 20260927113540.png]]
