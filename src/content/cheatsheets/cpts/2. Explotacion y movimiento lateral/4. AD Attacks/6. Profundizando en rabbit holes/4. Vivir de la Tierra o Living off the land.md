## Dsquery

[Dsquery](https://docs.microsoft.com/en-us/previous-versions/windows/it-pro/windows-server-2012-r2-and-2012/cc732952\(v=ws.11\)) es una herramienta que se puede usar para encontrar objetos de AD. Son consultas que se pueden replicar en BloodHound o PowerView

#### DLL de Dsquery

Lo unico que necesitamos son privs elevados en el host o capacidad de ejecutar una instancia CMD o PS como SYSTEM

1. Busqueda de usuarios

```
dsquery user
```
![[Pasted image 20260927132546.png]]

2. Busqueda de equipos

```
dsquery computer
```
![[Pasted image 20260927132614.png]]

3. Busqueda con comodines para ver los objetos de una OU

```
dsquery * "CN=Users,DC=INLANEFREIGHT,DC=LOCAL"
```
![[Pasted image 20260927132649.png]]

4. Combinar dsquery con filtros de busqueda LDAP. En la siguiente se localizan usuarios con el indicador PASSWD_NOTREQD establecido en el atributo userAccountControl

```
dsquery * -filter "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=32))" -attr distinguishedName userAccountControl
```
![[Pasted image 20260927132758.png]]

5. Busqueda de controladores de dominio

```
dsquery * -filter "(userAccountControl:1.2.840.113556.1.4.803:=8192)" -limit 5 -attr sAMAccountName
```
![[Pasted image 20260927132825.png]]


## Explicacion de filtrado LDAP

En las consultas estamos usando cadenas como: userAccountControl:1.2.840.113556.1.4.803:=8192. Estas son consultas LDAP comunes

userAccountControl:1.2.840.113556.1.4.803: --> estamos observando atributos de UAC de un objeto y puede cambiar dependiendo de OIDs


#### Valores UAC

![[Pasted image 20260927133025.png]]


Los OID son reglas utilizadas para hacer coincidir valores de bits con atributos. Para LDAP y AD, existen tres reglas de coincidencia principales::

1.  `1.2.840.113556.1.4.803` --> el bit debe coincidir completamente para cumplir con los requisitos de la búsqueda. Es ideal para hacer coincidir un único atributo.
2. `1.2.840.113556.1.4.804` --> queremos que nuestros resultados muestren cualquier coincidencia de atributo si cualquier bit en la cadena coincide. Esto funciona en el caso de que un objeto tenga múltiples atributos establecidos
3. `1.2.840.113556.1.4.1941` --> hacer coincidir filtros que se aplican al Nombre Distinguido (Distinguished Name) de un objeto y buscará a través de todas las entradas de propiedad y membresía


Al construir cadenas de búsqueda, podemos utilizar operadores lógicos `&`, `|` y `!`

`(&(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=64))`: El ejemplo anterior establece el primer criterio de que el objeto debe ser un usuario y lo combina con la búsqueda de un valor de bit UAC de 64 (Password Can't Change)

Puedes llevar esto aún más lejos y combinar múltiples atributos como `(&(1) (2) (3))`. Los operadores `!` (no) y `|` (o) pueden funcionar de manera similar

`(&(objectClass=user)(!userAccountControl:1.2.840.113556.1.4.803:=64))`
