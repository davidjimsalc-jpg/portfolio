## Permisos de escritura inseguros

Imagina que estamos en el host de un desarrollador y está trabajando con python 

Puede que, por error, uno u otro módulo de python tenga permisos de escritura para todos los usuario. Esto permite que el módulo de python sea editado y manipulado para que podamos insertar comandos o funciones que producirán los resultados que queremos 

Si nuestro usuario tiene permitido ejecutar el script de Python como `root` a través de `sudo`, nuestro código inyectado se ejecutará automáticamente con esos privilegios elevados

1. Verificacion de privs

```
sudo -l
```
![[Pasted image 20260921164531.png]]

	Podemos ejecutar `/home/htb-student/mem_status.py` como `root` usando `/usr/bin/python3`

2. Permisos del script

```
ls -l mem_status.py
```
![[Pasted image 20260921164627.png]]


Vemos que podemos ejecutar este script y también tenemos permiso para leer su contenido. No tenemos permiso de escritura; si lo tuviéramos, podríamos simplemente escribir nuestro payload directamente en `mem_status.py`

Además, notamos que el bit SUID está habilitado y el propietario del archivo es `root`. En una sección anterior, aprendimos que este permiso especial a veces se puede usar para la escalada de privilegios (privilege escalation). Sin embargo, por razones de seguridad, Linux ignora por defecto el bit SUID en los scripts interpretados (como los scripts de Python o Bash)


	Para que el bit SUID realmente nos conceda privilegios elevados aquí, necesitaría estar configurado directamente en el propio ejecutable de Python (`/usr/bin/python3`)

## Ruta de busqueda de bibliotecas Python

En Python, cada versión tiene un orden específico en el que se buscan e importan las bibliotecas

El orden en que Python importa los `módulos` se basa en un sistema de prioridades, lo que significa que las rutas más altas en la lista tienen prioridad

#### Listado PYTHONPATH

```
python3 -c 'import sys; print("\n".join(sys.path))'
```
![[Pasted image 20260922103823.png]]

Para poder utilizar esta variante, son necesarios dos requisitos previos.

1. El módulo que importa el script se encuentra en una de las rutas de menor prioridad listadas a través de la variable `PYTHONPATH`.
2. Debemos tener permisos de escritura en una de las rutas que tengan una prioridad más alta en la lista.

#### Ubicacion de instalacion predeterminada de Psutil

```
pip3 show psutil
```
![[Pasted image 20260922103938.png]]

`psutil` está instalado en la siguiente ruta: `/usr/local/lib/python3.8/dist-packages`

Del listado anterior deberemos mirar si alguna de las rutas anteriores tiene permisos de escritura

#### Permisos de directorio mal configurados

```
ls -la /usr/lib/python3.8
```
![[Pasted image 20260922104048.png]]

Parece que la ruta `/usr/lib/python3.8` está mal configurada de tal manera que permite a cualquier usuario escribir en ella

Podemos ver que esta ruta está más arriba en la lista que la ruta en la que está instalado `psutil`


#### Creacion de nuestro modulo psutil

Creamos nuestro propio modulo de psutil que contenga nuestra propia funcion maliciosa virutal_memory() en el directorio /usr/lib/python3.8

Archivo psutil.py:

```
#!/usr/bin/env python3 

import os 

def virtual_memory(): 
	os.system('id')
```
![[Pasted image 20260922104349.png]]

	El nombre del archivo debe ser el mismo que el modulo importado y la funcion debe tener el mismo numero de argumentos que la original

#### Ejecucion de mem_status.py

```
sudo /usr/bin/python3 mem_status.py
```

## Variable de entorno PYTHONPATH

Es una variable de entorno que indica en qué directorio (o directorios) Python puede buscar módulos para importar

Esto es importante, ya que si a un usuario se le permite manipular y establecer esta variable mientras ejecuta el binario de python, puede redirigir eficazmente la funcionalidad de búsqueda de Python a una ubicación `definida por el usuario`

1. Verificacion de privs sudo:

```
sudo -l
```
![[Pasted image 20260922104733.png]]

Podemos ejecutar python3 con sudo y cambiar sus variables al estar configurado con `SETENV:`

2. Escalada de privs mediante el secuestro de la variable PYTHONPATH

```
sudo PYTHONPATH=/tmp/ /usr/bin/python3 ./mem_status.py
```
![[Pasted image 20260922104955.png]]

Lo que hemos hecho es forzar a buscar los modulos importados en /tmp, si ahi tenemos un modulo malicioso que suplanta a uno que se importa en mem_status.py como psutil podremos escalar privs

	Es similar a lo que hicimos en el apartado anterior
