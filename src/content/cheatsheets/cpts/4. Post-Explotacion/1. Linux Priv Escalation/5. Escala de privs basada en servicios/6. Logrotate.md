
Los sistemas Linux tienen archivos de registro log files. Para evitar que el sistema se llene hay herrmientas como `logrotate` que se encarga de archivar o desechar los registros antiguos

Los registros en `/var/log` proporcionan a los admins la informacion que necesitan para determinar la causa de los fallos

`Logrotate` tiene muchas caracteristicas para gestionar estos archivos:

- Especificacion de tamaño
- Antiguedad
- Accion a realizar cuando se alcanza alguno de estos factores

![[Pasted image 20260920121757.png]]


La función de la rotación en sí consiste en renombrar los archivos de registro. Ejemplo: se crea una archivo llamado `log_new` el que era antes new pasa a renombrarse como `log_old`

`Logrotate` suele iniciarse con cron y se controla mediante `/etc/logrotate.conf` donde se encuentran las confs globales que determinan el funcionamiento de logrotate

![[Pasted image 20260920122004.png]]

#### Forzar rotacion

Para forzar una nueva rotacion ese mismo dia podemos establecer la fecha despues de los archivos de registro individuales de estado `/var/lib/logrotate.status` y usar -f

```
sudo cat /var/lib/logrotate.status
```
![[Pasted image 20260920122211.png]]

#### Archivos de conf

`/etc/logrotate.d/`

```
sudo cat /etc/logrotate.d/
```

## Explotar logrotate

Hay que cumplir alguno de los siguientes requisitos:

- Permisos de escritura en archvios de registro
- Logrotate debe ejecutarse como root o privs
- Versiones vulns:
	- 3.8.6
	- 3.11.0
	- 3.15.0
	- 3.18.0


[logrotten](https://github.com/whotwagner/logrotten): exploit prefabricado si se cumple alguno de los requisitos
