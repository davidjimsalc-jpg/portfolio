
Es un tipo de shell que limita la capacidad de ejecutar comandos permitiendo solo un par de ellos

Estas se usan para proporcionar un entorno seguro 

#### RBASH

La [shell Bourne restringida](https://www.gnu.org/software/bash/manual/html_node/The-Restricted-Shell.html) (`rbash`) es una version de shell Bourne que limita la capacidad del usuario para usar ciertas caracteristicas de Bourne como:

- Cambiar de directorio
- Establecer o modificar variables de entorno
- Ejecutar comandos en otros directorios

#### RKSH

La [shell Korn restringida](https://www.ibm.com/docs/en/aix/7.2?topic=r-rksh-command) (`rksh`) es una version de shell Korn que limita al usuario como:

- Ejecutar comandos en otros directorios
- Crear o modificar funciones de la shell
- Modificar el entorno de la shell


#### RZSH

La [shell Z restringida](https://manpages.debian.org/experimental/zsh/rzsh.1.en.html) (`rzsh`) es una versión de shell Z que limita al usuario como:

- Ejecutar scripts de shell
- Definir alias
- Modificar el entorno de la shell


Se pueden usar varios métodos para escapar de una shell restringida. Algunos de estos métodos implican explotar vulnerabilidades en la propia shell, mientras que otros implican usar técnicas creativas para eludir las restricciones impuestas por la shell


## Escapar

#### Inyecciones de comandos

Imagina que podemos ejecutar comandos y pasarles argumentos. En nuestro caso solo nos deja usar `ls` con un conjunto de argumentos como `ls -l` o `ls -a`

Para intectar comandos usaremos `'`

```
ls -l `pwd`
```

`ls` ejecutara `-l` seguido de la salida de `pwd` 


#### Sustitucion de comandos

Imagina que la shell permite a los usuarios ejecutar comandos encerrandolos entre `'` . En ese caso podriamos escapar de la shell ejecutando un comando entre `'`

Ejemplos: 

```
user=$(whoami)
echo "Hola: $user"
```

O con comillas:

```
echo "Hola: `whoami`"
```


#### Encadenamiento de comandos

Usar multiples comandos en una sola linea separados por `;` o `|`

```
ls;whoami
```


#### Variables de entorno

Tenemos que ser capaces de modificar o crear variables de entorno. Por ejemplo modificar la variable que especifica el direcotorio en el que se ejecutan los comandos (PATH) o creando una variable personalizada:

PATH:

```
PATH=.:${PATH}
export PATH
echo $PATH
COMANDO o SCRIPT
```

CREANDO VARIABLE:

```
user=$(whoami)
echo "Hola: $user"
```


#### Funciones de shell

Podriamos definir o invocar funciones de shell que ejecuten comandos no restringidos por shell. Digamos que la shell permite a los usuarios definir e invocar funciones de shell; podría ser posible escapar de la shell definiendo una función de shell que ejecute un comando

FUNCION NO SOPORTA ARGUMENTOS:

```
run_command() { $1 }
run_command whoami
```

FUNCION SI SOPORTA ARGUMENTOS:

```
run_command() { "$@" }
run_command ls -la
```
