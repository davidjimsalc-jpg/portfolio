
Algunas empresas habilitan el registro de linea de comandos para facilitar al blue team a supervisar e identificar posibles comportamientos maliciosos enviandolos a un SIEM. Estas herramientas marcarian como actividad potencialmente maliciosa comandos como whoami, netstat...

Ademas la empresa podria incluso restringir el uso de comandos especificos con reglas AppLocker

Los `Event Log Readers` tienen acceso a este registro

1. Confirmamos nuestra pertenencia al grupo

```
net localgroup "Event Log Readers"
```
![[Pasted image 20260910160233.png]]

	Muchos comandos usados en Windows tienen la contraseña en linea de comando, si la auditoria de linea de comando esta habilitada y como Event Log Reader podemos leerla podriamos encontrar algunas credenciales capturadas

2. Consultar los eventos desde linea de comandos: [wevtutil](https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/wevtutil) y [Get-WinEvent](https://docs.microsoft.com/en-us/powershell/module/microsoft.powershell.diagnostics/get-winevent?view=powershell-7.1)

```
wevtutil qe Security /rd:true /f:text | Select-String "/user"
```
![[Pasted image 20260910160546.png]]

Tambien podemos especificar credenciales en wevutil usando /u y /p por si fuese necesario:

```
wevtutil qe Security /rd:true /f:text /r:share01 /u:julie.clay /p:Welcome1 | findstr "/user"
```


3. Ejemplo con Get-WinEvent filtrando por creacion de eventos (EventID 4688): 

```
Get-WinEvent -LogName security | where { $_.ID -eq 4688 -and $_.Properties[8].Value -like '*/user*'} | Select-Object @{name='CommandLine';expression={ $_.Properties[8].Value }}
```

	-Credential: podemos ejecutarlo como otro usuario
