Son derechos que se pueden conceder a una cuenta para que realice una variedad de operaciones

Los privs de usuarios y grupos se almacenan en una BBDD y se conceden a traves de tokens por kerberos al iniciar sesion

Una cuenta puede tener unos privilegios locales en un sistema y distintos privilegios en otros si pertenece a un dominio

## Proceso de autorizacion Windows

Los security principals o Entidades de seguridad es cualquier cosa que pueda ser autenticada (usuarios, cuentas maquina...) y cada una se identifica con un SID

1. Se intenta acceder a un objeto protegible 
2. Se mira el token de acceso del usuario (contiene SID del usuario, SID del grupo al que pertenece, lista de privs y mas info de acceso)
3. Se compara con ACEs dentro del descriptor de seguridad del objeto (tiene info de seguridad de ese objeto)
4. Se toma la decision de si tiene acceso o no

## Derechos y privilegios Windows

| Grupo                       | Descripcion                                                                                                                                                      |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Default administrators      | super groups                                                                                                                                                     |
| Server Operators            | Pueden moficar serivicios, acceso de SMB Shares, backup files                                                                                                    |
| Backup Operators            | Tienen permitido iniciar sesion en el DC localmente y deben ser considerados como Domain Admins. Pueden hacer copias de SAM/NTDS, leer registros remotamente...  |
| Print Operators             | Miembros que se pueden loguear en el DC y engañar a Windows para que cargue controladores maliciosos                                                             |
| Hype-V Administrators       | Si hay DCs virtuales, estos deben ser considerados como Domain Admins                                                                                            |
| Account Operators           | Pueden modificar cuentas y grupos no protegidos del dominio                                                                                                      |
| Remote Desktop Users        | Permiten el inicio de sesion a traves de servicios de escritorio remoto                                                                                          |
| Remote Management Users     | Pueden iniciar sesion en los DCs con PSRemoting                                                                                                                  |
| Group Policy Creator Owners | Pueden crear GPOs pero necesitan que se les delegue permisos adicionales para vincular los GPOs a contenedores del dominio o OUs                                 |
| Schema Admins               | Pueden modificar la estrucutara del esquema AD y crear una puerta trasera en cualquier grupo/GPO añadiendo una cuentra comprometida a la ACL del objeto          |
| DNS Admins                  | Pueden cargar una DLL en el DC pero no tienen permisos para reiniciar el servidor DNS, por lo que tienen que esperar al reinicio DNS para conseguir persistencia |
