## Token de Acceso

En Windows, los [tokens de acceso](https://docs.microsoft.com/en-us/windows/win32/secauthz/access-tokens) se utilizan para describir el contexto de seguridad de un proceso o hilo. 

Este incluye informacion sobre la identidad y los privilegios de la cuenta de usuario relacionados con un proceso o hilo

Cuando nos autenticamos, se revisa en la BBDD la contraseña y si coincide nos daran un token de acceso y cada vez que interactuemos con un proceso se copia el token que determina nuestro nivel de privs

## Canalizaciones con nombre (Named Pipes)

Es una forma en la que los procesos se comunican entre si. Son esencialmente archivos almacenados en memoria que se borran despues de ser leidos

El flujo suele ser el siguiente:

- El proceso que ejecuta un comandos inica una canalizacion con nombre \.\pipe\msagent_12
- El proceso inica un proceso e inyecta el comando en ese proceso dirigiendo la salida a \.\pipe\msagent_12
- El servidor muestra la salida de  \.\pipe\msagent_12

Cobalt Strike hace esto con beacons (son los procesos que ejecutan comandos) porque el antivirus  lo bloqueaba pudiendo enmascararse como otro programa


#### Mas sobre las canalizaciones con nombre

Las canalizaciones se utilizan para la comunicación entre dos aplicaciones o procesos utilizando memoria compartida. Hay dos tipos de canalizaciones, [canalizaciones con nombre](https://docs.microsoft.com/en-us/windows/win32/ipc/named-pipes) y canalizaciones anónimas (anonymous pipes)

Un ejemplo de una canalización con nombre es `\\.\PipeName\\ExampleNamedPipeServer`. Los sistemas Windows utilizan una implementación cliente-servidor para la comunicación por canalización. En este tipo de implementación, el proceso que crea una canalización con nombre es el servidor, y el proceso que se comunica con la canalización con nombre es el cliente

Cada conexión activa a un servidor de canalización con nombre da como resultado la creación de una nueva canalización con nombre. Todas estas comparten el mismo nombre de canalización pero se comunican utilizando un búfer de datos diferente.

#### Revisar los permisos de la canalizacion con nombre de LSASS

Despues de obtener un listado, podemos usar [Accesschk](https://docs.microsoft.com/en-us/sysinternals/downloads/accesschk) para enumerar los permisos asignados a la canalizacion especifica revisando su DACL (Lista de Control de Acceso Discrecional) que nos muestra quien tiene los permisos para modificar, escribir, leer o ejecutar recursos

Si miramos por ejemplo la de LSASS

```
accesschk.exe /acceptula \\.\Pipe\lsass -v
```
![[Pasted image 20260806203622.png]]

De la salida anterior, podemos ver que solo los administradores tienen acceso completo al proceso LSASS

## Ejemplo ataque canalizacion con nombre

Miramos con `accesschk` que canalizaciones se pueden escribir y leer

```
accesschk.exe -w \pipe\* -v
```

Encontramos que `WindscribeService` tiene acceso READ y WRITE al grupo Everyone y el servicio que escucha al named pipe se esta ejecutando como SYSTEM

```
accesschk.exe -accepteula -w \pipe\WindscribeService -v
```
![[Pasted image 20260806204310.png]]

Podemos aprovechar que Everyone puede conectarse a \\\\.\pipe\WindscribeService. Escribimos en el archivo algo como `cmd.exe` o si espera un comando especifico podriamos poner:

```
switch(comando){
	case RUN_PROGRAM:
		CreateProcess("C:\\Users\\Public\\evil.exe");
		break;
}
```
