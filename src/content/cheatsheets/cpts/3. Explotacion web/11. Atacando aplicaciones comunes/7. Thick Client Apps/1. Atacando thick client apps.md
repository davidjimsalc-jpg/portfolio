
Son aplicaciones que se instalan localmente en nuestro equipo

A diferencia de los clientes ligeros que se ejecutan en remoto, estas no requieren acceso a Internet y tienen mejor rendimiento en cuanto a potencia de procesamiento, memoria y capacidad de almacenamiento

Se pueden clasificar en arquitecturas de 2 o 3 niveles:

- 2 niveles: se instala localmente y se comunica directamente con la base de datos
- 3 niveles: se instala localmente y para interactuar con la base de datos, primero se comunica con un servidor de aplicaciones usando HTTP/S. La BBDD puede estar en la misma red o en Internet (es mas segura ya que los atacantes no se pueden comunicar directamente con la BBDD)

## Pasos para Pentest

Es mas compleja y su superficie mas grande y se pueden hacer de forma automatizada o manualmente

#### Recopilacion de informacion

Hay que identificar la arquitectura de la aplicacion, lenguajes y frameworks. Ademas de entender como funciona la aplicacion y la infraestructura

Tambien se identifican tecns del lado del cliente y del servidor, puntos de entrada y entradas de usuario

Se buscan vulns comunes 

Herramietnas para recopilar info:

- [CFF Explorer](https://ntcore.com/?page_id=388
- [Detect It Easy](https://github.com/horsicq/Detect-It-Easy)
- [Process Monitor](https://learn.microsoft.com/en-us/sysinternals/downloads/procmon)
- [Strings](https://learn.microsoft.com/en-us/sysinternals/downloads/strings)|


#### Ataques del lado del cliente

Aunque los clientes pesados hacen procesamiento y almacenamiento significativo del lado del cliente, aun asi se comunican con servidores para diversas tareas como sincronizacion o acceso a recursos compartidos

Estas comunicaciones pueden exponer a los clientes pesados de vulnerabilidades similares a las de las aplicaciones web

Info sensible como nombres de usuarios, contraseñas, tokens o cadenas de comunicacion podrian almacenarse en archivos locales de la aplicacion

Credenciales codificadas en duro pueden encontrarse en el codigo fuente

Herramientas para ingenieria inversa y examinar aplicaciones en estatico:

| [Ghidra](https://www.ghidra-sre.org/)   | [IDA](https://hex-rays.com/ida-pro/) | [OllyDbg](http://www.ollydbg.de/)      | [Radare2](https://www.radare.org/r/index.html) |
| --------------------------------------- | ------------------------------------ | -------------------------------------- | ---------------------------------------------- |
| [dnSpy](https://github.com/dnSpy/dnSpy) | [x64dbg](https://x64dbg.com/)        | [JADX](https://github.com/skylot/jadx) | [Frida](https://frida.re/)                     |

El análisis dinámico también debe realizarse en este paso, ya que las aplicaciones de cliente pesado también almacenan información sensible en la memoria


#### Ataques de la red

Si la aplicacion se comunica con el servidor remoto, el analisis del trafico nos ayuda a capturar info sensible y nos dara una mejor comprension de como funciona

| [Wireshark](https://www.wireshark.org/) | [tcpdump](https://www.tcpdump.org/) | [TCPView](https://learn.microsoft.com/en-us/sysinternals/downloads/tcpview) | [Burp Suite](https://portswigger.net/burp) |

#### Ataques del lado del servidor

Son similares a los ataques a aplicaciones web, y los pentesters deben prestar atención a los más comunes


## Recuperando credenciales codificadas en duro de aplicaciones de cliente pesado

En este escenario hemos conseguido acceso a un SMB expuesto

Explorando NETLOGON del SMB encontramos la aplicacion `RestartOracle-Service.exe` entre otros archivos. La descargamos localmente y la ejecutamos en linea de comados donde parece o que no se ejecuta o que ejecuta algo oculto

![[Pasted image 20260728154744.png]]

Al descargar [ProcMon64](https://learn.microsoft.com/en-us/sysinternals/downloads/procmon) y monitorizando la ejecucion del proceso vemos que se crea un archivo temporal en `C:\Users\Matt\AppData\Local\Temp`

![[Pasted image 20260728154930.png]]

Para capturar este archivo debemos cambiar los permisos de `Temp` para que no los borre

	Click derecho en la carpeta > C:\Users\Matt\AppData\Local\Temp > Propiedades > Seguridad > Opciones avanzadas > cybervaca > Deshabilitar herencia > Convertir permisos heredados en permisos explícitos para este objeto > Editar > Mostrar permisos avanzados > Qutiamos la seleccion de Eliminar subcarpetas y archivos y Eliminar

![[Pasted image 20260728155132.png]]

	Aceptar > Aplicar > Aceptar > Aceptar

Volvemos a ejecutar `Restart-OracleService.exe` y al mirar `Temp` veremos el archivo `6F39.bat` creado en `C:\Users\cybervaca\AppData\Local\Temp\2`

![[Pasted image 20260728155251.png]]

Al mirar el contenido del archivo vemos lo siguiente:

![[Pasted image 20260728155324.png]]

Vemos que el batch crea dos archivos y elmina antes de que se puedan acceder. Si modificamso el script de batch para que no se eliminen podremos verlos eliminando la parte donde los borra:

![[Pasted image 20260728155456.png]]

Hacemos doble click sobre el batch para que se ejecute de nuevo y buscamos en `c:\programdata\` los archivos `oracle.txt y monta.ps1

Miramos el contenido del .ps1:

![[Pasted image 20260728155638.png]]


Como vemos solo coge el contenido que tiene el `oracle.txt` (son base64) y se lo pasa al ejecutable `restart-service.exe`. Si ejecutamos el .ps1 se creara el `restart-service.exe` que podremos examinar:

![[Pasted image 20260728155817.png]]

Si lo ejecutamos saldra lo siguiente:

![[Pasted image 20260728155840.png]]

Si monitorizamos la ejecucion de este .exe que no ejecuta nada a simple vista con `ProcMon64` muestra que esta consultando cosas en el registro y no muestra nada solido para continuar:

![[Pasted image 20260728155936.png]]


Como esta ejecutando cosas en memoria vamos a iniciar [x64dbg](https://x64dbg.com/):

	Options > Preferences > Desmarcamos todo excepto Exit Breakpoint

![[Pasted image 20260728160104.png]]

Esto hara que la depuracion comience directamente desde el punto de salida de la aplicacion y evitemos pasar por alguna dll que se cargue antes de la aplicacion

	File > Open > Restart-service.exe > Click derecho en la CPU > Follow in Memory Map

![[Pasted image 20260728160225.png]]

Mirando los mapas de memoria, ponemos interes en uno con tamaño `0000000000003000` de tipo `MAP` y proteccion `-rw--`. Los archivos mapeados en memoria permiten a las aplicaciones acceder a archivos grandes sin tener que leer o escribir por lo que podria ser un lugar potencial para buscar credenciales codificadas en duro

![[Pasted image 20260728160341.png]]


Al hacer doble click vemos los bytes magicos en la columna ACII que pone `MZ` indicando un archivo `DOS MZ`

![[Pasted image 20260728160548.png]]

Volvemos al panel de Memory Map y exportamos el elemento mapeado recien descubierto

	click derecho en la direccion de memoria > Dump memory to file

Ejecutamos strings en el archivo para ver la informacion:

![[Pasted image 20260728160736.png]]


Como vemos este registro de memoria contiene un .NET asi que usamos  [De4Dot](https://github.com/de4dot/de4dot) para revertir el .NET a su codigo fuente

	Lo ejecutamos y arrastramos el restart-service_MEMORIA.bin dentro 

Ahora, podemos leer el código fuente de la aplicación exportada arrastrándola y soltándola sobre el ejecutable `DnSpy`

![[Pasted image 20260728161104.png]]

Con el código fuente revelado, podemos entender que este binario es un `runas.exe` hecho a medida con el único propósito de reiniciar el servicio de Oracle
