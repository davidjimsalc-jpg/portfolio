
[Apache Tomcat](https://tomcat.apache.org/) servidor open source que aloja aplicaciones escritas en Java y scripts en JSP


## Descubrimiento y Footprinting

En EyeWitness en la categoria de activos de alto valor, vemos un host que parece estar ejecutando Tomcat

Para confirmar de que se trata de Tomcat:

- Al capturar la solicitud con Burp, mirar la cabecera Server
- Podemos visitar una pagina no valida, y si el servidor esta detras de un proxy inverso, podremos ver la version:

![[Pasted image 20260727110305.png]]

A veces puede que se hayan personalizado las paginas de error para no mostrar informacion del servidor. En este caso podemos ir al directorio /docs:

```
curl -s "http://.../docs" / grep Tomcat
```
![[Pasted image 20260727110434.png]]

Esta es la pagina de documentacion por defecto que puede que los administradores no hayan eliminado

#### Carpetas de Tomcat predeterminadas

![[Pasted image 20260727110535.png]]


- /bin: binarios y scripts para la ejecucion de Tomcat
- /conf: archivos de configuracion 
	- /conf/tomcat-users.xml: credenciales de usuario y roles designados
- /lib: archivos JAR necesarios para el funcionamiento de Tomcat
- /logs y /temp: archivos de registros temporales
- /webapps: webroot de Tomcat donde aloja las aplicaciones
- /work: actua como cache


Estructura de `/webapps`:

![[Pasted image 20260727110838.png]]

`WEB-INF/web.xml`: es el archivo mas importante. Almacena info como:

- Rutas usadas por la aplicacion
- Clases JAVA que manejan esa ruta
	- Las clases JAVA se deben meter en: `/WEB-INF/classes/` las cuales contienen la logica

#### Ejemplo de web.xml:

![[Pasted image 20260727111220.png]]

Vemos que hay un servlet llamado AdminServlet que se mapea en: `com.inlanefreight.api.AdminServlet` que se traduce a la ruta --> 

`/com/inlanefreight/api/AdminServlet.class`

Despues se crea un mappeo que hace que las solicitudes que vayan a `/admin/` se redirijan a `AdminServlet.class`



#### Ejemplo /conf/tomcat-users.xml

![[Pasted image 20260727111725.png]]

Vemos diferentes roles en los comentarios como:

En el ejemplo vemos:

## Enumeracion

Una vez que identifiquemos que se trata de Tomcat y a menos que haya una vuln conocida, querremos mirar los directorios de:

	/manager y /host-manager


```
gobuster dir -u http://web01.inlanefreight.local:8180/ -w /usr/share/dirbuster/wordlists/directory-list-2.3-small.txt
```
![[Pasted image 20260727112127.png]]

Una vez conozcamos estos directorios, podemos intentar entrar a verlos probando credenciales debiles de Apache Tomcat como:

	admin:admin
	tomcat:tomcat
	...

Si no funciona ya probaremos un ataque de fuerza bruta en el login
