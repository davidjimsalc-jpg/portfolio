La entrada se añadio a la pagina, y si no hay saneamiento o filtrado a nuestra entrada, la pagina podria ser vulnerable a XSS


## Payloads de prueba

- Introducimos este payload de prueba y le damos a enter:

```
<script>alert(window.origin)</script>
```

Si no hay sanetizacion y la pagina permite cualquier entrada, al restablecer la pagina se debe mostrar la URL de la pagina en una ventana emergente:

![[Pasted image 20260715201446.png]]

Con esto ya hemos confirmado que el XSS es real pero si entramos a ver el codigo fuente encontraremos nuestro payload

![[Pasted image 20260715201600.png]]

	Actualmente las paginas web usan iFrames por cada dominio por lo que si la vulnerabilidad XSS se detecta en este formulario puede que no sea vulnerable en toda la aplicacion. Por ello se uso window.origin (un valor dinamico que muestra desde donde se ejecuto el payload)


\<alert> puede ser bloqueado por algunos navegadores
\<plaintext> detendra la renderizacion de lo que viene despues y mostrara el codigo HTML de despues sin formato
\<script>print()\</script> abre el dialogo de impresion del navegador el cual es poco probable que sea bloqueado por el navegador


Si al actualizar la pagina el payload se sigue ejecutando es que era XSS almacenado/persistente
