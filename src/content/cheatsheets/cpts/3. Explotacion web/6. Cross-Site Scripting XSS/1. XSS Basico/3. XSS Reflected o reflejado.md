
Tipo de XSS no persistente que se procesa completamente del lado del cliente y nunca llega al servidor backend

Estas son temporales y no persisten a actualizaciones de pagina por lo que solo afectan al objetivo y no a cualquier usuario que visite la pagina

Ocurre cuando el servidor devuelve la entrada del usuario en la respuesta y sin filtrarla. Si la entrada contenia codigo JS el navegador lo ejecuta. En este caso la entrada se envia al backend en forma de solicitudes HTTP aunque no los almacena


## Ejemplo practico

Imaginemos el mismo caso anterior de una pagina web de lista de tareas. Intentamos agregar test y nos sale "Task test could not added" el cual incluye nuestra entrada en la respuesta --> test

![[Pasted image 20260716105225.png]]

Ahora vamos a probar con un codigo JS y le damos a Add:

![[Pasted image 20260716105316.png]]

Obtenemos una ventana emergente porque como en la respuesta que se nos envia se encontraba nuestra entrada pues se acabo ejecutando en el lado del cliente

![[Pasted image 20260716105622.png]]

En el mensaje de error ahora nos dice "Task '' could not added" ya que nuestra entrada no es renderizada por estar entre \<script>, pero si vamos a ver el codigo fuente podemos confirmar que esta dentro del '' del mensaje de error

![[Pasted image 20260716105826.png]]

Si actualizamos la pagina o volvemos a entrar ya no aparecera el mensaje


## ¿Entonces como atacamos a otros?

Pues lo primero que debemos hacer es mirar en que solicitud HTTP se envian los datos al backend

Si le damos a inspeccionar > network > ponemos cualquiercosa > add o miramos la peticion desde burp, en este caso veremos que es una solicitud HTTP GET

![[Pasted image 20260716110127.png]]

Estas envian los parametros dentro de la URL, por lo que para atacar a otro usuario podemos pasarle la URL con los parametros de payload. Una vez que la visite obtendra la salida del payload

![[Pasted image 20260716110245.png]]
