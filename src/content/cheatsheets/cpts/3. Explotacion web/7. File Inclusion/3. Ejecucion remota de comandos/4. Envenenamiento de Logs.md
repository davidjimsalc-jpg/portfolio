## Envenenamiento de sesiones PHP (PHP Session Poisoining)

La mayoria de aplicaciones usan cookies `PHPSESSID` que pueden contener datos especificos relacionados con el usuario en backend para que la aplicacion pueda hacer un seguimiento del usuario

Estos se suelen almacenar en archivos de `session` en el backend y se guardan en:

- Linux: /var/lib/php/sessions
- Windows: C:\Windows\Temp\

El nombre de los archivos empieza con: `sess_`

Ejemplo: `/var/lib/php/sessions/sess_el4ukv0kqbvoirg7nkp4dncpk3`


1. Miramos a ver si tenemos PHPSESSID establecida

![[Pasted image 20260720141614.png]]

Como vemos en el archivo hay 2 parametros:

- Page -> indica el archivo de lenguaje que se muestra (tenemos control ya que podemos controlarlo a traves de `?language=`)
- Preference -> muestra el lenguaje seleccionado (de este no tenemos control porque no podemos especificarlo por ninguna parte)

## Envenenamiento de logs del servidor

Apache y Nginx tienen varios archivos de logs como `access.log` y `error.log`

- Access.log: tiene informaicon sobre todas las solicitudes hechas al servidor incluyendo el parametro UserAgent

En Nginx la lectura de estos archivos se puede hacer con usuarios de privilegios bajos mientras que en los Apache modernos solo deja con usuarios con privs

Rutas:

- Apache: 
	- Linux: /var/log/apache2/
	- Windows: C:\xampp\apache\logs\

- Nginx: 
	- Linux: /var/log/nginx/
	- Windows: C:\nginx\log\

Si no lo encontramos podemos hacer fuzzing usando [LFI Wordlist](https://github.com/danielmiessler/SecLists/tree/master/Fuzzing/LFI)

- `/var/log/sshd.log`
- `/var/log/mail`
- `/var/log/vsftpd.log`

Primero deberíamos intentar leer estos logs a través de LFI, y si tenemos acceso a ellos, podemos intentar envenenarlos como hicimos anteriormente

SSH Y FTP: iniciar sesion con un usuario que tenga como nombre codigo PHP
MAIL: enviar un correo electronico que contenga codigo PHP
