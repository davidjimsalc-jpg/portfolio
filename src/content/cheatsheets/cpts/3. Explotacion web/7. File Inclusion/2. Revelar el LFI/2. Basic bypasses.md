
## Filtros no recursivos de path traversal

Filtros que tratan de evitar el uso de `../`

![[Pasted image 20260717225855.png]]![[Pasted image 20260717225902.png]]

Este codigo lo que hace es cambiar la cadena de texto `../` por nada. Entonces podemos usar por ejemplo `....//` para bypasearlo porque una vez que lo elimine quedaria `../` y como no es recursivo no se volveria a quitar

![[Pasted image 20260717230008.png]]

Ejemplos de bypasses:

- `....//`
- `..././`
- `....\/`
- `....////`


## Codificacion

Algunos filtros web pueden prevenir la entrada de `. o /` por lo que podemos codificarlos en formato URL

La codificacion en URL de `../` es --> %2e%2e%2f 

Ademas podemos codificarla varias veces si fuese necesario

## Rutas aprobadas

Algunas aplicaciones web pueden imponer que el archivo que se visite este dentro de una ruta especifica usando REGEX. Por ejemplo que solo acepte rutas que esten debajo de ./languages

![[Pasted image 20260717230545.png]]

Para encontrar la ruta correcta (en este caso ./languages) podemos examinar las peticiones enviadas y ver que ruta usan para la funcionalidad normal de la web

Tambien podemos hacer fuzzing de directorios bajo la misma ruta y poder probar hasta que obtengamos una coincidencia

Para evadirlo comenzamos con la ruta correcta y seguimos con path traversal --> `./languages/../../../../etc/passwd`

![[Pasted image 20260717230802.png]]

Algunas aplicaciones combinan esto con filtros por lo que podemos probar combinaciones


## Extension añadida

Algunas veces se nos impondra una extension (ej .php) que se pondra al final de todas las consultas para evitar que miremos otros archivos que no sean .php

En versiones modernas es posible que no podamos evadirlo y estaremos restringidos a ver .php pero puede seguir siendo util

Hay tecnicas de evasion para versiones mas antigua de la 5.3 y 5.4

#### Truncamiento de ruta

En versiones antiguas de PHP las cadenas definidas tienen una longitud max de 4096caracteres. Si se pasa una cadena mas larga, esta se truncara y cualquier caracter despues de la longitud sera ignorado

Otro truncamiento pasaba cuando se añadia al final `/.` esto era eliminado por PHP. Si poniamos `/etc/passwd/.` se quedaria en `/etc/passwd`. Tambien pasa al poner varias `/` como `////etc/passwd` quedaria en `/etc/passwd` o con un `.` en medio `/etc/./passwd` que quedaria `/etc/passwd`

La combinacion de todas se puede ver tal que asi:

![[Pasted image 20260717231657.png]]

Para escribirlo podemos usar scripts en bash:

```
echo -n "non_existing_directory/../../../etc/passwd" && for i in {1..2048}; do echo -n "./";done
```

Se pueden añadir mas `../` hasta que nos lleven al directorio raiz

Todos los caracter `/.` se eliminaran


#### Bytes nulos

Las versiones anteriores 5.5 eran vulns a inyeccion de bytes nulos --> `%00`

La adicion de bytes nulos al final de la cadena hacia que la cadena se terminase y no se considerara lo que venia despues

Ejemplo: si en el include() nos obligan a mirar .php pero ponemos `/etc/passws%00` el resultado seria `/etc/passws%00.php` pero lo que hay despues del caracter nulo se elimina y quedaria `/etc/passwd`
