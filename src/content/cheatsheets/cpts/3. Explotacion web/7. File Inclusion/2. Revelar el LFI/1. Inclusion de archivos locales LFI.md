## Prefijo de nombre de archivo

Otro ejemplo sucede cuando al parametro tiene un prefijo añadido como `lang_VALOR`:

![[Pasted image 20260717202914.png]]

Si añadimos `../../../etc/passwd` en realidad la include() leera `lang_../../../etc/passwd` y dara error:

![[Pasted image 20260717203003.png]]

Una forma de eludir esto es añadiendo `/` antes del `../../../etc/passwd`. Esto se debe a que es posible que `lang_/` exista como directorio dentro del sistema backend. Si no existiese daria error

Entonces include leerira algo como `lang_/../../../etc/passwd`

![[Pasted image 20260717203238.png]]

## Ataques LFI de segundo orden

Son un poco mas avanzados

Imaginemos que podemos descargar una imagen de una pagina web a traves de una URL que ve asi:

```
/profile/$username/avatar.png
```

Podriamos crear un usuario con un nombre como `../../../etc/passwd` y al descargar la imagen en realidad nos cargaria el archivo local

El nombre de usuario normalmente se guardaria en una BBDD y normalmente las sanetizaciones estan en las entradas que podemos cambiar pero no en las entradas que tienen de la BBDD
