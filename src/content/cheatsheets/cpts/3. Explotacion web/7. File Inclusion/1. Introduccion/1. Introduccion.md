En muchos lenguajes de backend se usan parametros HTTP para especificar el recurso que se muestra en la pagina web, con esto se reduce el tamaño del script y se simplifica el codigo

El problema esta en que si no se codifican de forma segura, se pueden modificar estos parametros para mostrar otros recursos locales


## Inclusion de archivos locales LFI

Un ejemplo suele ser una pagina web que carga sus partes estaticas (encabezado, barra de navgacion, pie de pagina...) y luego muestra de forma dinamica otro contenido que cambia entra paginas

Normalmente la parte dinamica se especifica con un parametro dentro de la URL --> /index.php?PARAMETRO=VALOR donde index.php seria la parte estatica y luego solo extrae contenido dinamico en el parametro que en este caso se leera de about.php

Puede llevar a:

- Filtracion de codigo fuente (que puede ser probado para encontrar nuevas vulns)
- Exposicion de datos sensibles
- Ejecucion de comandos en ciertas condiciones


## Ejemplos de codigos vulneables en backend

Imaginemos el ejemplo en el que segun el idioma muestra un contenido u otro

El parametro del HTTP GET sera ?language=VALOR
El valor sera es o en

El cambio de valor puede incluso hacer que cambiemos el directorio desde el que la aplicacion muestra la pagina cargada (/es/ o /en/)


#### PHP

La funcion `include()` se usa para mostrar el archivo local o remoto mientras cargamos la pagina
Si el parametro que le pasamos a `include()` esta controlado por el usuario en un parametro GET y el codigo no filtra de forma adecuada la entrada entonces se vuelve vuln a LFI
