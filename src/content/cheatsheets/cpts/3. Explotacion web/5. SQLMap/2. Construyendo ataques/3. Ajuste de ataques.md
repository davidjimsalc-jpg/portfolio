
En general no haran falta pero hay flags y opciones que ayudan en la fase de la deteccion

Cada payload enviado tiene dos partes:

- vector (UNION ALL SELECT 1,2,VERSION()): parte central del payload que lleva el codigo SQL
- delimitadores o boundaries ('\<vector>-- -): prefijos y sufijos usados para la inyeccion correcta de la sentencia

## Prefijo/Sufijo

En casos en los que la ejecucion normal de la herramienta no cubra algunos casos, podemos especificarlos

```
sqlmap -u "www.example.com/?q=test" --prefix="%'))" --suffix="-- -"
```

Esto pondra lo siguiente:

```
%')) <vector> -- -
```

## Nivel/Riesgo

--level \[1-5]: amplia vectores y delimitadores que se usan en funcion de la expectativa de exito (default=1)

--risk \[1-3]: amplia el conjunto de vectores usados en funcion del riesgo que pueden causar (default=1)

Junto con -v 3 mostraran los payloads usados

## Ajuste avanzado

#### Codigos de estado

Cuando se trata de un objetivo muy grande con mucho contenido dinamico donde las respuestas entre `TRUE` y `FALSE` son minimas podemos usar los codigos de estado

--code=200: fijar las respuestas TRUE


#### Titulos

Si la diferencia puede observarse con los titulos de la pagina HTTP

--titles: mirara la etiqueta HTML \<title>


#### Cadenas de texto

Omite la comparacion de etiquetas como \<script>, \<style>, \<meta> y solo compara el contenido textual

--text-only


#### Tecnicas

Para especificar el tipo de payload que se usa

--technique=BEU --> Boolean-based blind, error-based y UNION-query


#### Ajuste de ineyccion SQL UNION

Si encontramos informacion de forma manual que necesita la consulta UNION como el numero de columnas lo podemos especificar

--union-cols=N --> Los valores de relleno por defecto se rellenan con NULL
--union-char='a' --> especificamos que el valor de relleno sera una caracter a
--union-from=TABLA --> añadir
