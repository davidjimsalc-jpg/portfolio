
Sucede cuando una aplicacion web expone una refencia directa a un objeto como un archivo, recurso de BBDD o ID

Si cualquier usuario puede acceder a contenido de otros objetos debido a falta de controles de acceso se considera vulnerable

Ejemplo: el usuario solicita acceso a uno de sus archivos recientemente subido y obtiene una URL asi `download.php?file=123`. El enlace hace referencia al `file = 123`, ¿que pasaria si tratamos de poner `download.php?file=124`? 

Si la aplicacion web nos muestra el archvio con ID 124 es vulnerable. Hay casos en los que el ID es facil de adivinar y casos en los que no


## Que constituye una vulnerabilidad IDOR

El simple hecho de exponer una referencia directa a un objeto o recurso no es la vulnerabilidad, sino el bajo control de acceso a estos en el backend

La mayoria de desarrolladores ignoran la construccion de un sistema de control de acceso y lo unico que impediria acceder a los recursos de otros usuarios serian las restricciones del frontend

## Impacto

El ejemplo más básico de una vulnerabilidad IDOR es acceder a archivos y recursos privados de otros usuarios que no deberían ser accesibles para nosotros

Dependiendo de la naturaleza de la referencia directa expuesta, la vulnerabilidad puede incluso permitir la modificación o eliminación de los datos de otros usuarios, lo que puede llevar a una toma de control completa de la cuenta

Una vez se identifica el patron del ID del objeto se pueden probar patrones especificos para ver si puede obtener acceso a algun dato

También pueden llevar a la elevación de privilegios de un usuario estándar a un usuario administrador
