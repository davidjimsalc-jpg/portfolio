
## Parametros de URL y API

Primero hay que identificar las referencias a objetos

Cada vez que recibimos un archivo o recurso debemos estudiar las peticiones HTTP para buscar parametros URL o API con referencia a ese objeto:

`?uid=1` o `?filename=file_1.pdf`

Estos son ejemplo basicos que podrian ser IDORs si al poner un 2 hicieramos referencia a otro objeto y se nos mostrase: `?uid=2` o `?filename=file_2.pdf`

## Entender el hashing/codificacion

Algunas aplicaciones pueden no usar numeros secuenciales para referenciar los objetos sino que pueden codificar la referencia o aplicarle un hash

Supongamos la siguiente referencia: `?filename=ZmlsZV8xMjMucGRm` esto es un BASE64 que podemos decodificar y ver que la referencial original es `?file_123.pdf`

O puede ser una hash como: `?filename=c81e728d9d4c2f636f067f89cc14862c`

Si miramos el codigo fuente podemos ver que se esta hasheando antes de que se haga la llamda a API y que se usa CryptoJS.MD5:
