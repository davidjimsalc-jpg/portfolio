
Tenemos que probar metodos HTTP alternativos para ver como los maneja el webserver y la aplicacion

Muchas herramientas miran bastante bien las configuraciones inseguras pero pasan por alto las codificaciones inseguras. Esto se debe a que el primero se puede identificar facilmente al omitir la pagina de autenticacion y el segundo necesita de pruebas activas para ver si podemos eludir los filtros de seguridad


## Identificar

Vemos una aplicacion web basica de administrador de archivos en la que podemos añadir nuevos archivos escribiendo sus nombres y pulsando enter:

![[Pasted image 20260723220033.png]]

Si le damos a Reset se borraran todos los archivos, pero esta funcionalidad esta restringida para usuarios autenticados con una Autenticacion basica HTTP:

![[Pasted image 20260723220124.png]]

Como no sabemos las credenciales nos dara un 401:

![[Pasted image 20260723220143.png]]

Vamos a caturar la solicitud HTTP al darle a Reset. Vemos que esta llamando a /admin/reset.php con un GET

Esto quiere decir o que /admin esta restringido o que /admin/reset.php esta restringido
Si visitamos /admin vemos que efectivamente todo el directorio esta restringido


## Explotar

![[Pasted image 20260723220422.png]]

Vemos que la solicitud es un GET, podemos tratar de enviar un POST y ver si la pagina web incluye la autenticacion para metodos POST

Click derecho > Change Request Method y se cambia a POST:

![[Pasted image 20260723220526.png]]

Podemos darle a forward y examinar si hemos eludido el inicio de sesion. Obtendremos la pagina 401 por lo que no habra funcionado:

![[Pasted image 20260723220629.png]]

Esto indica que las configuraciones cubren tanto GET como POST. Pero podemos usar otros muchos metodos como HEAD (que es identico a GET pero no devuelve el cuerpo)

Para ver si la pagina web permite solicitudes HEAD podemos mandar una solicitud con el metodo OPTIONS y vemos que si lo permite:

![[Pasted image 20260723220757.png]]


Volvemos a capturar la solicitud HTTP del Reset de nuevo y en vez de POST al cambiar el metodo, pondremos HEAD para ver como lo maneja el servidor web:

![[Pasted image 20260723220910.png]]

Habremos bypasseado la autenticacion porque no nos pone un 401 y se han borrado los archivos:

![[Pasted image 20260723221025.png]]

## Ejemplo practico

Trata de entrar en reset.php para borrar los archivos y ver la flag

1. Visitamos la pagina web y con el burp activado le damos a reset. La solicitud que obtenemos la mandamos al repeater

![[Pasted image 20260723221147.png]]![[Pasted image 20260723221207.png]]

2. Si le damos a forward veremos el panel de autenticacion basica

![[Pasted image 20260723221236.png]]

3. En el repeater empezamos mandando el GET y nos dice 401

![[Pasted image 20260723222044.png]]

4. Cambiamos el request method a POST y nada 401, lo mismo con HEAD

![[Pasted image 20260723221252.png]]![[Pasted image 20260723222059.png]]
![[Pasted image 20260723222114.png]]

![[Pasted image 20260723222131.png]]
