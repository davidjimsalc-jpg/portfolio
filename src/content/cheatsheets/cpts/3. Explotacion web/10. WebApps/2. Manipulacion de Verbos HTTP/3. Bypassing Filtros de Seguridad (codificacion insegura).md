
Son errores durante el desarrollo que hace que no se cubran todos los metodos HTTP en ciertas funcionalidades. Se detecta comunmente en los filtros de seguridad que detectan solicitudes maliciosas

Ejemplo: si el filtro de codigo que detecta inyeccion de comandos solo verifica las solicitudes POST ($\_POST\['parametro']), podriamos evadirlo usando una solicitud GET


## Identificar

En la aplicacion de Gestor de archivos intentamos crear un archivo `test;` y obtenemos malicious Reuqest Denied!:

## Ejemplo practico

Trata de poner el nombre al archivo `file; cp /flag.txt ./` para obtener la flag

1. Visitamos la pagina web y tratamos de poner ese nombre al archivo para obtener la flag. El burp debe estar activo para interceptar la solicitud HTTP

![[Pasted image 20260723223820.png]]

2. Lo mandamos al repeater

![[Pasted image 20260723223837.png]]

3. Si lo mandamos asi con el GET nos dara Malicious Request Denied! (la flag que sale es la de la seccion anterior que estaba ya en la pagina web)

![[Pasted image 20260723223858.png]]

4. Cambiamos el metodo y se pone como POST. Si le damos a enviar vemos que ahora no da error

![[Pasted image 20260723223910.png]]![[Pasted image 20260723223935.png]]

5. Vamos a la pagina web y recargamos, veremos flag.txt. Si la visitamos veremos la flag

![[Pasted image 20260723223950.png]]![[Pasted image 20260723224002.png]]
