
Cuando una aplicacion web confia en datos XML sin filtrar provenientes de la entrada de un usuario, es posible que podamos hacer referencia a un documento DTD externo y definir nuevas ENTITIES XML personalizadas

Podriamos crear ENTITIES que hicieran referencia a un archivo local lo que deberia poder enseñarnos su contenido

## Identificacion

Primero hay que encontrar una pagina web que acepte una entrada de usuario en formato XML. Empezaremos con la siguiente pagina de Formulario de Contacto:

![[Pasted image 20260724232837.png]]

Si rellenamos este formulario y al enviarlo capturamos la solicitud HTTP veremos que el formulario parece estar enviando nuestros datos en formato XML conviritiendolo en un objetivo para XEE

![[Pasted image 20260724232922.png]]


Vamos a suponer que usa bibliotecas XML desactualizadas y no aplica filtros o sanetizacion de entrada. Podriamos explotar el formulario para leer archivos locales

Primero lo enviamos desde Repeater sin ninguna modificacion:

![[Pasted image 20260724233051.png]]


Estamos viendo como el valor de "email" se devuelve en la respuesta. Entonces email sera el objetivo a vulnerar

Por ahora sabemos que cualquier valor que pongamos en email se mostrara

1. Definiremos nuestra ENITITY (en este ejemplo no hay un DOCTYPE que ya haga referencia a un DTD por lo que lo creamos de 0, si existiese solo creamos el ENTITY)

```
<!DOCTYPE email [ <!ENTITY company "Inlane Freight"> ]>
```
![[Pasted image 20260724233252.png]]

2. Lo introducimos en el XML (como ya sabemos despues de la declaracion XML) y hacemos referencia a el (en la parte de email para que se muestre en la respuesta)

![[Pasted image 20260724233434.png]]


## De otros formatos a XML

Hay aplicaciones que mandan los archivos en, por ejemplo, JSON pero siguen aceptando XML. Para ello:

1. Cambiamos el Content-Type --> `application/xml`
2. Cambiamos el JSON por XML en --> [Herramienta de JSON a XML](https://www.convertjson.com/json-to-xml.htm)


## Lectura de archivos sensibles

Ahora crearemos una ENTITY usando SYSTEM y definiremos la ruta del archivo a leer

```
<!DOCTYPE email [ <!ENTITY company SYSTEM "file:///etc/passwd"> ]>
```
![[Pasted image 20260724233726.png]]

Si lo introducimos en la solicitud veremos en la respuesta el archivo:

![[Pasted image 20260724233746.png]]


Podemos leer incluso los id_rsa

Podemos ver el modulo de LFI para ver que ataques podemos usar con la divulgacion de archivos locales


## Lectura del codigo fuente

![[Pasted image 20260724233901.png]]


Vemos que no nos devuelve nada y es debido a que falla al ser referenciado como una entidad XML externa. Si contiene `< > &`, podria romper la referencia a la entidad y por eso no se muestra

Podemos usar PHP Wrappers y Filters para pasarlo a BASE64

```
<!DOCTYPE email [
  <!ENTITY company SYSTEM "php://filter/convert.base64-encode/resource=index.php">
]>
```

## Ejecucion remota de codigo con XXE

El metodo mas facil seria buscar las claves SSH o robar hashes de aplicaciones web basadas en Windows

Si no funciona podemos usar `php://expect` aunque requiere que expect este instalado y habilitado

Podemos probar con un basico:

```
<!DOCTYPE email [
  <!ENTITY company SYSTEM "expect://id">
]>
```

Este se usa para enumerar puertos abiertos localmente y acceder a sus paginas entre otras paginas web restringidas
